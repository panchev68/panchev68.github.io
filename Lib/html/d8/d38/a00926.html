Lib::BSP::RFID::MFRC522::Card Class Reference

Description

Handles card detection, selection, authentication, and encrypted communication with proximity cards. Talks to the card over RF through Chipset::transceive(), which drives the MFRC522's FIFO/COMMAND-register sequence.

bool Lib::BSP::RFID::MFRC522::Card::authenticate ( uint8_t blockAddress,
bool keyType,
const uint8_t * key )
inline

Performs key-based authentication using either key A or key B, required before reading or writing data on the block. Uses the UID captured by the most recent selectCard() call, as required by the MIFARE authentication protocol. Delegates to Chipset::executeAuthentication(), which drives the dedicated MF_AUTHENT hardware command; the chip itself reports success via the STATUS2 MFCrypto1On flag.

Parameters
blockAddressThe target block address on the card.
keyTypeSelection between key A ('true') or key B ('false').
keyPointer to a 6-byte array containing the authentication key.
Returns
'true' if authentication succeeds, 'false' otherwise.

◆ halt()

bool Lib::BSP::RFID::MFRC522::Card::halt ( )
inline

The card will not respond to commands until it is removed from and reinserted into the MFRC522's field, or until selectCard() is called again.

Returns
Always 'true'. A PICC does not acknowledge the HALT command, so a timeout on this exchange is the expected, successful outcome and cannot be distinguished from a communication failure by this return value.

◆ selectCard()

bool Lib::BSP::RFID::MFRC522::Card::selectCard ( )
inline

Must be called after detectCard() returns 'true'. First runs anticollision (NVB 0x20) to read the 4 UID bytes and verify their BCC checksum, then sends a genuine SELECT frame (NVB 0x70, CRC protected) built from that UID to obtain the real SAK from the card. The UID and SAK are stored internally and can be retrieved using getUid().

Returns
'true' if selection succeeds, 'false' otherwise.
