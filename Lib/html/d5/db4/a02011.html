RTOS::Mutex Class Referencefinal

Description

Every lock() that returns true must be paired with exactly one unlock() by the same task; prefer RTOS::MutexGuard to get that pairing automatically. Never lock or unlock from an ISR.

Examples
RTOS::MutexGuard.

◆ lock() [2/2]

bool RTOS::Mutex::lock ( TickType timeout = WAIT_FOREVER)
inlinenodiscardnoexcept

Task context only.

The mutex must already be open via open(); calling this while closed returns false without attempting to create the underlying handle, since lazily creating a synchronization primitive from within itself is not thread-safe. A recursive mutex may be locked again by its owner; every lock needs its own unlock().
