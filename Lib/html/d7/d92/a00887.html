Lib::BSP::EncoderTimer Class Referencefinal

Description

Reports rotation steps and push-button transitions (push, release, hold) as events. Direction comes from the hardware direction bit, so it stays correct when the counter wraps around. Several steps between two read() calls are reported as one event.

The driver is poll-based: hold detection and rotation sampling happen only inside read(), so call it periodically from one task.

◆ read()

EventCode Lib::BSP::EncoderTimer::read ( )
inlinenodiscardnoexcept

Checks in priority order: a button level change, then a rotation step, then an expired hold time. Repeated levels caused by contact bounce are filtered out, so every push is followed by exactly one release.

Returns
Detected event, or EventCode::NONE if nothing happened.
Precondition
