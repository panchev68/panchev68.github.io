Lib::BSP::Display::TouchGFX_BW

Shows a TouchGFX application on a 128 x 64 SSD1306 OLED with Lib::BSP::Display::TouchGFX_BW.

Shows a TouchGFX application on a 128 x 64 SSD1306 OLED with Lib::BSP::Display::TouchGFX_BW.TouchGFX renders into a black and white frame buffer, one bit per pixel, and tells the HAL which rectangle changed in TouchGFXHAL::flushFrameBuffer(). The bridge turns the changed 8 x 8 blocks into the pages of the OLED and sends the frame, and a software timer gives TouchGFX its vertical-sync tick. The bridge holds no TouchGFX type, so the three connections, the frame buffer with its rectangle, the sync callback and the display driver, are plain arguments written here once. The OLED transfer takes about 25 ms on I2C at 400 kHz, so the sync period is set to 25 ms: a shorter one only makes TouchGFX render frames that are never shown.

Important
Lib::BSP::Display::TouchGFX_BW::update() blocks on the panel transfer and runs in the TouchGFX task, never in an interrupt. The generated HAL has to use the 1-bit black and white frame buffer format; the bridge reads WIDTH / 8 bytes per row.

Display, sync and TouchGFX task

The display is opened before TouchGFX starts rendering. The vertical-sync callback is the static touchgfx::OSWrappers::signalVSync, bound without any glue code. The TouchGFX task is the one that the generated code provides as TouchGFX_Task.

#include <Lib/BSP/Display/SSD1306.hpp>
#include <Lib/BSP/Display/TouchGFX_BW.hpp>
#include <Lib/HAL/I2C.hpp>
#include <RTOS.hpp>
#include <touchgfx/hal/HAL.hpp>
#include <touchgfx/hal/OSWrappers.hpp>
#include <touchgfx/hal/Types.hpp>
#include <chrono>
extern "C" I2C_HandleTypeDef hi2c1; // Generated by CubeMX in main.c.
extern "C" void TouchGFX_Task(void *); // Generated by TouchGFX.
Lib::HAL::I2CPort<Lib::HAL::DriverMode::IT> i2cPort{&hi2c1};
Lib::BSP::Display::SSD1306<128, 64> oled{{.i2cPort = i2cPort}};
Lib::BSP::Display::TouchGFX_BW<Lib::BSP::Display::SSD1306<128, 64>> bridge{{
.display = oled,
.onVSync = FunctionRef<void()>::fromFunction<&touchgfx::OSWrappers::signalVSync>(),
.vsyncPeriod = std::chrono::milliseconds(25),
}};
RTOS::Task touchGfxTask;
// Call once at start-up, after the generated TouchGFX initialization.
[[nodiscard]] bool startDisplay() noexcept {
if (!oled.open()) {
return false; // Port failed to open or the display did not acknowledge.
}
touchgfx::HAL::getInstance()->lockDMAToFrontPorch(false);
if (!bridge.start()) {
return false;
}
touchGfxTask.setup(RTOS::Task::Config("TouchGFX", 1024, RTOS::Task::Priority::NORMAL));
return touchGfxTask.start([]() noexcept { TouchGFX_Task(nullptr); }) != nullptr;
}
// Called from TouchGFXHAL::flushFrameBuffer(), see below.
void updateDisplay(const touchgfx::Rect & rect) noexcept {
const auto * frame = reinterpret_cast<const uint8_t *>(touchgfx::HAL::getInstance()->getTFTFrameBuffer());
static_cast<void>(bridge.update(frame, rect.x, rect.y, rect.width, rect.height));
}

The flush hook

The one change to the generated HAL file TouchGFX/target/TouchGFXHAL.cpp: send the changed rectangle to the bridge, then call the parent so that TouchGFX knows the flush is done. A rectangle without changes sends nothing to the panel.

extern void updateDisplay(const touchgfx::Rect & rect) noexcept;
void TouchGFXHAL::flushFrameBuffer(const touchgfx::Rect & rect) {
updateDisplay(rect);
TouchGFXGeneratedHAL::flushFrameBuffer(rect);
}
