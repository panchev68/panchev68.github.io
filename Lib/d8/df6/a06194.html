Lib::HAL::SPIPort

Runs full-duplex and half-duplex transfers on an SPI bus with Lib::HAL::SPIPort in its three modes, selected by the template argument 'Lib::HAL::DriverMode::BLOCKING', 'Lib::HAL::DriverMode::IT' or 'Lib::HAL::DriverMode::DMA'.

Runs full-duplex and half-duplex transfers on an SPI bus with Lib::HAL::SPIPort in its three modes, selected by the template argument 'Lib::HAL::DriverMode::BLOCKING', 'Lib::HAL::DriverMode::IT' or 'Lib::HAL::DriverMode::DMA'. All three share one public surface, Lib::HAL::SPIPortBase::send(), Lib::HAL::SPIPortBase::receive() and Lib::HAL::SPIPortBase::sendReceive(), so only the constructed mode changes.

The port takes a native SPI_HandleTypeDef generated by CubeMX. It has no Config struct: the mode, clock and pins come from the CubeMX-generated MX_SPIx_Init(), and Lib::HAL::SPIPortBase::open() calls HAL_SPI_Init() on that handle. Every transfer is bracketed by optional begin and end hooks, which typically drive a chip-select pin. A transfer takes a buffer of 1 to 65535 bytes and a timeout as any std::chrono::duration.

Blocking transfers

The blocking mode runs each call to completion in the calling task: the HAL polls the peripheral until the transfer finishes or the timeout expires.

#include <Lib/HAL/GPIO.hpp>
#include <Lib/HAL/SPI.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern SPI_HandleTypeDef hspi1;
bool readDeviceId(Lib::HAL::GPIO::Output & chipSelect) noexcept {
Lib::HAL::SPIPort<Lib::HAL::DriverMode::BLOCKING> port(&hspi1);
if (!port.open()) {
return false;
}
std::array<uint8_t, 4> command{0x9FU, 0x00U, 0x00U, 0x00U};
std::array<uint8_t, 4> reply{};
chipSelect.setLow();
const bool isExchanged = port.sendReceive(command, reply, std::chrono::milliseconds(10));
chipSelect.setHigh();
static_cast<void>(port.close());
return isExchanged;
}

Begin and end transaction hooks

Lib::HAL::SPIPortBase::bindBeginTransactionFunc() and Lib::HAL::SPIPortBase::bindEndTransactionFunc() register a callback that runs before and after every Lib::HAL::SPIPortBase::send(), Lib::HAL::SPIPortBase::receive() and Lib::HAL::SPIPortBase::sendReceive() call. Use them to assert and release chip select, so every call is framed without repeating the pin code. The end hook runs only after the hardware has stopped, including after a timeout.

The hooks are non-owning references (FunctionRef), so the callable must outlive the binding.

#include <Lib/HAL/SPI.hpp>
#include <array>
extern SPI_HandleTypeDef hspi1;
namespace {
void selectFlash() noexcept {
HAL_GPIO_WritePin(FLASH_CS_GPIO_Port, FLASH_CS_Pin, GPIO_PIN_RESET);
}
void deselectFlash() noexcept {
HAL_GPIO_WritePin(FLASH_CS_GPIO_Port, FLASH_CS_Pin, GPIO_PIN_SET);
}
} // namespace
void writeEnable(Lib::HAL::SPIPort<Lib::HAL::DriverMode::BLOCKING> & port) noexcept {
port.bindBeginTransactionFunc(selectFlash);
port.bindEndTransactionFunc(deselectFlash);
constexpr std::array<uint8_t, 1> WRITE_ENABLE{0x06U};
static_cast<void>(port.send(WRITE_ENABLE, std::chrono::milliseconds(5)));
}

Interrupt-driven transfers

The IT mode starts the transfer, then blocks the calling task on an RTOS event group until the HAL completion or error interrupt signals it or the timeout expires. The task yields while the bus is busy, and the call asserts when it is made from an ISR. On a timeout or an error the port aborts the transfer itself and returns false. Lib::HAL::SPIPortAsync::abort() is for a different task that must release a transfer already in progress.

Important
The port registers its own HAL callbacks in Lib::HAL::SPIPortBase::open(), so the HAL configuration must set USE_HAL_SPI_REGISTER_CALLBACKS to 1, or the translation unit fails to compile. The CubeMX-generated SPIx_IRQHandler() must be enabled in the NVIC.
#include <Lib/HAL/SPI.hpp>
#include <RTOS.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern SPI_HandleTypeDef hspi2;
class DisplayTask final {
public:
DisplayTask() noexcept :
port(&hspi2),
task(RTOS::Task::Config("Display", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::SPIPort<Lib::HAL::DriverMode::IT> port;
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!port.open()) {
return;
}
std::array<uint8_t, 8> frame{};
while (true) {
// Fill frame, then push it out; the task sleeps until the transfer completes.
static_cast<void>(port.send(frame, std::chrono::milliseconds(20))); // false: the port has already aborted it.
RTOS::delay(std::chrono::milliseconds(10));
}
}
};

DMA transfers

The DMA mode has the same public calls and blocking policy as IT; the data moves by DMA. The buffers must lie in memory the DMA controller can reach. On an F4 part that means not in CCM RAM: each DMA start asserts Lib::HAL::isDmaReachable() on its buffers.

#include <Lib/HAL/SPI.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern SPI_HandleTypeDef hspi3;
// Static storage in ordinary SRAM, not CCM RAM.
static std::array<uint8_t, 256> frameBuffer{};
bool pushFrame(Lib::HAL::SPIPort<Lib::HAL::DriverMode::DMA> & port) noexcept {
return port.send(frameBuffer, std::chrono::milliseconds(50));
}
