Lib::HAL::Timer::TimPwmOutput

Drives one PWM channel with Lib::HAL::Timer::TimPwmOutput.

Drives one PWM channel with Lib::HAL::Timer::TimPwmOutput. The wrapper starts and stops the channel and changes its duty cycle and period through the timer registers. It has no interrupt and no task wait. Lib::HAL::Timer::TimPwmOutput::setPulse() and Lib::HAL::Timer::TimPwmOutput::setPeriod() are single register writes, so they can be called from task or ISR context.

The timer must already be configured by CubeMX in PWM mode on the chosen channel, including the prescaler and period. The wrapper does not call HAL_TIM_PWM_Init() and does not change the prescaler.

Hardware and CubeMX assumptions

  • Timer (here TIM3) in PWM Generation mode on the channel (TIM_CHANNEL_1), with the output pin set as alternate function.
  • The period (ARR) and prescaler are set in CubeMX; the wrapper only writes ARR through Lib::HAL::Timer::TimPwmOutput::setPeriod().
  • One Lib::HAL::Timer::TimPwmOutput per channel. The wrapper does not enforce this: two objects on one channel write the same CCR register.

Start with a duty cycle

The output keeps running after the function returns. The destructor does not stop it, so call Lib::HAL::Timer::TimPwmOutput::close() on the same object to stop the waveform.

#include <Lib/HAL/TIM/TimPwmOutput.hpp>
#include <cstdint>
void startFan(Lib::HAL::Timer::TimPwmOutput & fan) noexcept {
// Pulse width in timer ticks; the duty cycle is pulse / (period + 1).
fan.setPulse(fan.getPeriod() / 2U);
if (!fan.open()) {
return;
}
}

Changing duty cycle and period at run time

Lib::HAL::Timer::TimPwmOutput::setPulse() writes the CCRx register directly. Whether a new value takes effect at the next update event depends on the output-compare preload set in CubeMX, which the wrapper does not change.

Lib::HAL::Timer::TimPwmOutput::setPeriod() writes ARR directly and changes the period of every channel of the timer. Without ARR preload, a value below the running counter lets the counter overshoot to its maximum before it wraps.

#include <Lib/HAL/TIM/TimPwmOutput.hpp>
#include <cstdint>
void setSpeed(Lib::HAL::Timer::TimPwmOutput & fan, uint32_t percent) noexcept {
const uint32_t clampedPercent = (percent > 100U) ? 100U : percent;
const uint64_t periodPlusOne = static_cast<uint64_t>(fan.getPeriod()) + 1U;
fan.setPulse(static_cast<uint32_t>(periodPlusOne * clampedPercent / 100U));
}
void setFrequency(Lib::HAL::Timer::TimPwmOutput & fan, uint32_t periodTicks) noexcept {
fan.setPeriod(periodTicks);
}

Error handling

Lib::HAL::Timer::TimPwmOutput::open() returns false when the HAL start request fails. The wrapper does not retry; the caller decides what to do next.

#include <Lib/HAL/TIM/TimPwmOutput.hpp>
#include <cassert>
void startOrReport(Lib::HAL::Timer::TimPwmOutput & output) noexcept {
if (!output.open()) {
assert(!"PWM channel failed to start; check CubeMX PWM configuration");
return;
}
}
