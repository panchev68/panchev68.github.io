Lib::HAL::USBDevicePort

Drives the USB controller through the port layer: 'Lib::HAL::USBDevicePort' for the device role, 'Lib::HAL::USBHostPort' for the host role, and Lib::HAL::USBOtgPort, which switches one controller between the two.

Drives the USB controller through the port layer: 'Lib::HAL::USBDevicePort' for the device role, 'Lib::HAL::USBHostPort' for the host role, and Lib::HAL::USBOtgPort, which switches one controller between the two. The port wraps the CubeMX 'PCD_HandleTypeDef' (device) and 'HCD_HandleTypeDef' (host) and reports bus and transfer events; it does not implement a USB class. For the CDC class built on this layer see 'Lib_USB_CDCDevice.dox'.

Only the 'IT' and 'DMA' specializations exist. There is no 'BLOCKING' mode, because a USB endpoint transfer completes in a later interrupt, not inside a call. The lifecycle calls ( 'Lib::HAL::USBDevicePort::open()', 'Lib::HAL::USBDevicePort::start()', the endpoint calls and 'Lib::HAL::USBDevicePort::send()' / 'Lib::HAL::USBDevicePort::receive()' ) are task context only, while the event handler runs in interrupt context and must call only the interrupt-safe submit functions. The CubeMX 'OTG_FS_IRQHandler()' must call HAL_PCD_IRQHandler() for a device role and HAL_HCD_IRQHandler() for a host role.

Important
The device and host classes compile only when 'HAL_PCD_MODULE_ENABLED' and 'HAL_HCD_MODULE_ENABLED' are defined in the HAL configuration header. That header is not part of this repository, so the guards are unverified here. STM32F407 has the USB OTG controller, so the modules are expected to be available on that target.
Warning
Both specializations require 'USE_HAL_PCD_REGISTER_CALLBACKS' and 'USE_HAL_HCD_REGISTER_CALLBACKS' set to 1 in the HAL configuration header; otherwise the build stops with a compile-time error.

Device role

Set the event handler before 'Lib::HAL::USBDevicePort::start()'. The handler receives a 'context' pointer, a Lib::HAL::USBDeviceEvent and, for 'IN_COMPLETE' and 'OUT_COMPLETE', an endpoint number. For a 'SETUP' event the handler reads the request with 'Lib::HAL::USBDevicePort::getSetupPacket()'. Inside the handler use only 'Lib::HAL::USBDevicePort::submitSend()' and 'Lib::HAL::USBDevicePort::submitReceive()'; the buffers they reference must stay valid until the matching event arrives.

#include <Lib/HAL/USB.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <span>
extern PCD_HandleTypeDef hpcd_USB_OTG_FS;
namespace {
constexpr uint8_t BULK_IN = 0x81U; // Endpoint 1, IN direction.
constexpr uint8_t BULK_OUT = 0x01U; // Endpoint 1, OUT direction.
constexpr uint32_t RX_FIFO_WORDS = 128U;
std::array<uint8_t, 64> txBuffer{};
std::array<uint8_t, 64> rxBuffer{};
// Runs in interrupt context: only the interrupt-safe submit calls are used here.
void onDeviceEvent(void * context, Lib::HAL::USBDeviceEvent event, uint8_t endpoint) noexcept {
auto * device = static_cast<Lib::HAL::USBDevicePort<Lib::HAL::DriverMode::IT> *>(context);
if ((event == Lib::HAL::USBDeviceEvent::OUT_COMPLETE) && (endpoint == 1U)) {
static_cast<void>(device->submitReceive(BULK_OUT, rxBuffer));
}
}
} // namespace
bool startDevice(Lib::HAL::USBDevicePort<Lib::HAL::DriverMode::IT> & device) noexcept {
device.setEventHandler(&onDeviceEvent, &device);
if (!device.open()) {
return false;
}
static_cast<void>(device.setRxFifo(RX_FIFO_WORDS));
static_cast<void>(device.setTxFifo(1U, 32U));
if (!device.openEndpoint(BULK_IN, 64U, Lib::HAL::USBEndpointType::BULK) ||
!device.openEndpoint(BULK_OUT, 64U, Lib::HAL::USBEndpointType::BULK) ||
!device.submitReceive(BULK_OUT, rxBuffer)) {
return false;
}
return device.start() && device.connect();
}
// Task context: waits for the host to configure the bus, then sends a block.
bool sendReport(Lib::HAL::USBDevicePort<Lib::HAL::DriverMode::IT> & device) noexcept {
if (!device.waitForEvent(Lib::HAL::USBDeviceEvent::RESET, std::chrono::seconds(5))) {
return false;
}
return device.send(BULK_IN, std::span<const uint8_t>(txBuffer).first(16U), std::chrono::milliseconds(100));
}

Device role with DMA

The DMA specialization has the same API. The handle must be created with 'Init.dma_enable' set to 1, and every buffer passed to the port must be 4-byte aligned and reachable by the DMA controller.

#include <Lib/HAL/USB.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <span>
extern PCD_HandleTypeDef hpcd_USB_OTG_FS;
alignas(4) static std::array<uint8_t, 64> dmaTx{};
bool sendDma(Lib::HAL::USBDevicePort<Lib::HAL::DriverMode::DMA> & device) noexcept {
return device.send(0x81U, std::span<const uint8_t>(dmaTx), std::chrono::milliseconds(100));
}

Host role

The host port opens the controller, starts it, waits for a device to attach, and resets the port. Each endpoint of the attached device gets a channel with 'Lib::HAL::USBHostPort::openChannel()'; after that 'Lib::HAL::USBHostPort::transfer()' moves data on it and returns a Lib::HAL::USBHostTransferResult. The result 'NOT_READY' asks the caller to submit the same transfer again.

#include <Lib/HAL/USB.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <span>
extern HCD_HandleTypeDef hhcd_USB_OTG_FS;
bool readDeviceDescriptor(Lib::HAL::USBHostPort<Lib::HAL::DriverMode::IT> & host) noexcept {
if (!host.open() || !host.start()) {
return false;
}
if (!host.waitForEvent(Lib::HAL::USBHostEvent::CONNECT, std::chrono::seconds(5))) {
return false;
}
if (!host.resetPort() || !host.waitForEvent(Lib::HAL::USBHostEvent::PORT_ENABLED, std::chrono::seconds(1))) {
return false;
}
const Lib::HAL::USBSpeed speed = host.getSpeed();
// Channel 0 talks to address 0 (the default address) on endpoint 0, the control pipe.
if (!host.openChannel(0U, 0U, 0U, speed, Lib::HAL::USBEndpointType::CONTROL, 8U)) {
return false;
}
// The setup packet is a standard GET_DESCRIPTOR request, 8 bytes.
std::array<uint8_t, 8> setup{0x80U, 0x06U, 0x00U, 0x01U, 0x00U, 0x00U, 0x12U, 0x00U};
if (host.transfer(0U, Lib::HAL::USBDirection::OUT, Lib::HAL::USBEndpointType::CONTROL, true, setup, std::chrono::milliseconds(100)) != Lib::HAL::USBHostTransferResult::DONE) {
return false;
}
std::array<uint8_t, 18> descriptor{};
const Lib::HAL::USBHostTransferResult result = host.transfer(0U, Lib::HAL::USBDirection::IN, Lib::HAL::USBEndpointType::CONTROL, false, descriptor, std::chrono::milliseconds(100));
return (result == Lib::HAL::USBHostTransferResult::DONE) && (host.getTransferCount(0U) == descriptor.size());
}

Dual-role OTG controller

Lib::HAL::USBOtgPort owns one device port and one host port over the same controller. Only one role is initialized at a time: Lib::HAL::USBOtgPort::setRole() deinitializes the old role before it opens the new one. The role is usually taken from the ID pin read by the caller, passed through Lib::HAL::USBOtgPort::roleFromIdPin(). The ports of the OTG class are the 'IT' specializations.

#include <Lib/HAL/USB.hpp>
extern PCD_HandleTypeDef hpcd_USB_OTG_FS;
extern HCD_HandleTypeDef hhcd_USB_OTG_FS;
bool useRoleFromIdPin(Lib::HAL::USBOtgPort & otg, bool isIdPinLow) noexcept {
const Lib::HAL::USBRole role = Lib::HAL::USBOtgPort::roleFromIdPin(isIdPinLow);
if (!otg.setRole(role)) {
return false;
}
if (role == Lib::HAL::USBRole::DEVICE) {
return otg.getDevice().start();
}
return otg.getHost().start();
}
