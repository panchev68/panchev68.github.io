Description

Graphics layer for one-bit displays: text, widgets and the display contract.

Provides the Lib::GUI::Context, the singleton that holds the whole configuration of the GUI, including the current drawing area, and owns the parts below, the Lib::GUI::Display, which holds the size and the pixel functions of the driver, such as Lib::BSP::Display::SSD1306, bound once by the application, the Lib::GUI::Primitives shape drawing on it, the Lib::GUI::Canvas text helper over the primitives, the Lib::GUI::Font access to bitmap fonts held in a Lib::GUI::FontData (for example from Lib::GUI::LcdVision::parse()), the Lib::GUI::Position type, and the widgets Lib::GUI::String, Lib::GUI::ProgressBar and Lib::GUI::ListMenu. Nothing is a template on the display, so one instance of each class serves the whole program.

◆ FontLayout

enum class Lib::GUI::FontLayout : uint8_t
strong

Order in which the pixels of one glyph are stored in the font data.

In every layout a set bit is a lit pixel. The two vertical layouts take (height + 7) / 8 bytes per column of the glyph with bit 0 as the top row of a byte; the horizontal layout takes (width + 7) / 8 bytes per row with bit 0 as the leftmost column of a byte.

See also
Source
Enumerator
COLUMNS 

Column by column; the bytes of one column follow each other, from the top eight rows downwards.

VERTICAL_ROWS 

Rows of vertical bytes: all columns of the top eight rows, then all columns of the next eight rows.

HORIZONTAL_ROWS 

Row by row; the bytes of one row follow each other, from the left.
