Lib::HAL::Timer::TimPwmOutput

Drives one PWM channel with Lib::HAL::Timer::TimPwmOutput.

Drives one PWM channel with Lib::HAL::Timer::TimPwmOutput. The wrapper starts and stops the channel and changes its duty cycle and period through the timer registers. It has no interrupt and no task wait, so every method is safe to call from task context; Lib::HAL::Timer::TimPwmOutput::setPulse() can also be called from an ISR, but it is not synchronized with other writers.

The timer must already be configured by CubeMX in PWM mode on the chosen channel, including the prescaler and period. The wrapper does not call HAL_TIM_PWM_Init() and does not change the prescaler.

Usage

Hardware and CubeMX assumptions

  • Timer (here 'TIM3') in PWM Generation mode on the channel ('TIM_CHANNEL_1'), with the output pin set as alternate function.
  • The period (ARR) and prescaler are set in CubeMX; the wrapper only writes ARR through Lib::HAL::Timer::TimPwmOutput::setPeriod().
  • Only one Lib::HAL::Timer::TimPwmOutput per channel; two objects on the same channel fight over the same CCR register.

Start with a duty cycle

#include <Lib/HAL/TIM/TimPwmOutput.hpp>
void startFan(TIM_HandleTypeDef * timHandle) noexcept {
Lib::HAL::Timer::TimPwmOutput fan(timHandle, TIM_CHANNEL_1);
// Pulse width in timer ticks; the duty cycle is pulse / (period + 1).
fan.setPulse(fan.getPeriod() / 2U);
if (!fan.open()) {
return;
}
// Run the output until the object is closed or destroyed.
static_cast<void>(fan.close());
}

Changing duty cycle and period at run time

Writing the pulse width while the channel runs takes effect on the next update event only if the CubeMX configuration enables preload. Without preload the new value applies immediately, which can produce a short glitch.

#include <Lib/HAL/TIM/TimPwmOutput.hpp>
void setSpeed(Lib::HAL::Timer::TimPwmOutput & fan, uint32_t percent) noexcept {
const uint32_t period = fan.getPeriod();
const uint32_t clampedPercent = (percent > 100U) ? 100U : percent;
fan.setPulse((period + 1U) * clampedPercent / 100U);
}
void setFrequency(Lib::HAL::Timer::TimPwmOutput & fan, uint32_t periodTicks) noexcept {
fan.setPeriod(periodTicks);
}

Error handling

Lib::HAL::Timer::TimPwmOutput::open() returns false when the HAL rejects the start request, typically because the handle is in an unexpected state or the channel was not configured in CubeMX. The wrapper does not retry.

void startOrReport(Lib::HAL::Timer::TimPwmOutput & output) noexcept {
if (!output.open()) {
assert(!"PWM channel failed to start; check CubeMX PWM configuration");
return;
}
