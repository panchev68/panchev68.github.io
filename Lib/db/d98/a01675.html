RTOS::Mutex::LockGuard Class Reference

Description

LockGuard class for RAII locking.

Automatically locks the mutex on construction and unlocks on destruction. This RAII (Resource Acquisition Is Initialization) wrapper ensures that mutexes are properly unlocked even if exceptions occur or early returns happen.

The LockGuard attempts to acquire the mutex during construction with an optional timeout. If the lock is acquired, it will be automatically released when the LockGuard goes out of scope. The lock status can be checked using isLocked() or the bool conversion operator.

Usage example:

{
MutexGuard guard(myMutex, 100); // Try to lock for 100 ticks
if (guard) {
// Critical section - mutex is locked
// ...
} // Mutex automatically unlocked here
}

Constructor of LockGuard class.

Attempts to acquire the mutex lock with the specified timeout. If the lock is successfully acquired, it will be automatically released when the LockGuard is destroyed.

Parameters
mutexReference to the mutex to lock.
timeoutTimeout for locking in ticks. Use Mutex::WAIT_FOREVER for infinite wait.
Note
If timeout is 0, the constructor performs a non-blocking lock attempt.
The mutex must be valid (created) before using LockGuard.

Destructor of LockGuard class.

Automatically unlocks the mutex if it was successfully acquired during construction. This ensures proper resource cleanup and prevents deadlocks.

Note
Only unlocks if the lock was acquired; safe to call even if lock failed.
Destructor is to ensure it never throws exceptions.
