Lib::HAL::RTCDevice

Reads and sets the real-time clock with Lib::HAL::RTCDevice and delivers a once-per-second tick to an observer from a worker task.

Reads and sets the real-time clock with Lib::HAL::RTCDevice and delivers a once-per-second tick to an observer from a worker task.The device registers itself with Lib::HAL::DeviceManager on construction, so the HAL alarm callback can map the native handle back to the instance. startTickService() creates an RTOS task and arms Alarm A; the observer is a non-owning Lib::HAL::RTCDevice::Callback, so the function it refers to must outlive the service.

The header defines the C-linkage HAL_RTC_AlarmAEventCallback() itself. Do not define that callback in CubeMX user code or anywhere else, or the link fails with a duplicate symbol.

Important
The RTC is available on every STM32F4xx family, including the STM32F407xx target of this library. The module guard is HAL_RTC_MODULE_ENABLED; the project's 'stm32f4xx_hal_conf.h' is not in the repository, so that guard is unverified here, although the STM32Cube template enables it.
Warning
Lib::HAL::RTCDevice::setDateTime() and Lib::HAL::RTCDevice::startTickService() assert that they run in task context, not in an ISR. Lib::HAL::RTCDevice::stopTickService() blocks until the worker task exits. Called from the tick observer itself, it only requests the stop and must not wait on the worker, so the observer must return.

Read and set date and time

#include <Lib/HAL/RTC/RTCDevice.hpp>
extern RTC_HandleTypeDef hrtc; // Generated by CubeMX.
static Lib::HAL::RTCDevice rtcDevice(&hrtc);
void setInitialClock() noexcept {
const Lib::HAL::RTCDevice::Time time{.hours = 12U, .minutes = 30U, .seconds = 0U};
const Lib::HAL::RTCDevice::Date date{.year = 26U, .month = 11U, .day = 13U, .weekDay = RTC_WEEKDAY_FRIDAY};
if (!rtcDevice.setDateTime(time, date)) {
// The HAL refused the write; the clock keeps its previous value.
}
}

The weekday must agree with the day of the month; Lib::HAL::RTCDevice::setDateTime() checks only that it lies between RTC_WEEKDAY_MONDAY and RTC_WEEKDAY_SUNDAY.

Per-second tick observer

The observer runs in the worker task, so it may call RTOS services, but it must not block for longer than one second or the next tick is delayed.

#include <Lib/HAL/RTC/RTCDevice.hpp>
extern RTC_HandleTypeDef hrtc; // Generated by CubeMX.
static Lib::HAL::RTCDevice rtcDevice(&hrtc);
void onTick(const Lib::HAL::RTCDevice::Time & time, const Lib::HAL::RTCDevice::Date & date) {
// Update the display or log the time. Keep it short.
static_cast<void>(time);
static_cast<void>(date);
}
bool startClockTicks() noexcept {
return rtcDevice.startTickService(onTick);
}
void stopClockTicks() noexcept {
rtcDevice.stopTickService();
}

Error path

Lib::HAL::RTCDevice::startTickService() returns false when the service already runs, and also when the observer is unbound (which asserts in a debug build), when the worker task cannot be created, or when the Alarm A configuration is refused. In the last two cases the service is left stopped, so a retry is safe. Lib::HAL::RTCDevice::getDateTime() returns false when either HAL read fails; the output parameters are then not written and must not be used.

#include <Lib/HAL/RTC/RTCDevice.hpp>
extern RTC_HandleTypeDef hrtc; // Generated by CubeMX.
static Lib::HAL::RTCDevice rtcDevice(&hrtc);
bool readClock(Lib::HAL::RTCDevice::Time & time, Lib::HAL::RTCDevice::Date & date) noexcept {
return rtcDevice.getDateTime(time, date);
}
