Lib::BSP::GSM::A7670E

Powers the SIMCom A7670E modem on and off, sends an AT command, waits for the network, reads the signal, time and position, sleeps and wakes the modem, and stores files in the modem flash.

Powers the SIMCom A7670E modem on and off, sends an AT command, waits for the network, reads the signal, time and position, sleeps and wakes the modem, and stores files in the modem flash. The driver does not know the board: the application passes a Lib::HAL::StreamSerialPort, the PWRKEY, RESET and STATUS pins, an optional DTR pin and a FunctionRef callback that switches the modem supply, all in one Lib::BSP::GSM::A7670E::Config. The functions are grouped: Lib::BSP::GSM::A7670E::Power for the supply and sleep, Lib::BSP::GSM::A7670E::Network for registration, time and position, and Lib::BSP::GSM::A7670E::Files for whole files. Lib::BSP::GSM::A7670E::File gives handle-based access for appends and partial transfers.

Warning
Use the modem from one task only. The driver is task context only, and only one task may read the serial port.
Important
The application's supply callback must switch the modem supply on: the driver calls it with true before powering the modem and with false after a failed power-on or a power-off.
The UART handle must be configured with USE_HAL_UART_REGISTER_CALLBACKS, because the serial port receives continuously.
Warning
Lib::BSP::GSM::A7670E::Files::write() erases and rewrites the whole file in the modem flash, so write only when the content changes.

Hardware configuration

The serial port and the pins are plain objects owned by the application, declared once and referred to by the driver.

  • 'PIN()' expands to the _GPIO_Port and _Pin symbols that CubeMX emits in 'main.h'; the handles must outlive the wrappers that use them, so they are declared as 'constexpr' at namespace scope.
  • 'DTR' is optional. Passing nullptr instead of '&dtr' disables UART sleep, and Lib::BSP::GSM::A7670E::Power::sleep() then returns false.
  • FunctionRef accepts a plain function, so the supply callback can be an ordinary function that drives a regulator enable pin.
#include <Lib/BSP/GSM/A7670E.hpp>
#include <Lib/HAL/GPIO.hpp>
#include <Lib/HAL/UART/StreamSerialPort.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <optional>
#include <string_view>
extern "C" UART_HandleTypeDef huart3; // Generated by CubeMX in 'usart.c'.

using Modem = Lib::BSP::GSM::A7670E;
// CubeMX pin labels; each 'PIN()' expands to the matching port and pin symbols.

constexpr Lib::HAL::GPIO::Handle RESET_PIN = PIN(MODEM_RESET);
constexpr Lib::HAL::GPIO::Handle STATUS_PIN = PIN(MODEM_STATUS);
constexpr Lib::HAL::GPIO::Handle DTR_PIN = PIN(MODEM_DTR);
constexpr Lib::HAL::GPIO::Handle SUPPLY_PIN = PIN(MODEM_SUPPLY_EN);

Power on and off

Lib::BSP::GSM::A7670E::Power::on() drives the supply, pulses PWRKEY and waits until the modem answers 'AT'. It also turns the command echo off and enables numeric error codes.

  • On failure the driver closes the port and cuts the supply again, so the caller only returns.
  • Lib::BSP::GSM::A7670E::Power::off() sends 'AT+CPOF', waits for the shutdown and then cuts the supply. Call it before removing the supply by other means.

void powerCycle() {
if (!modem.power().on()) {
return; // The modem did not answer in time; the driver has already cut the supply again.
}
// The modem is on: the AT channel works and the command echo is off.
static_cast<void>(modem.power().isOn());
modem.power().off(); // Detaches from the network with 'AT+CPOF' if the modem answers, then cuts the supply.
}

AT command

Lib::BSP::GSM::A7670E::sendCommand() sends one command, waits for the final result and returns it. The command text is given without the carriage return, which the driver adds.

  • Pass a buffer of Lib::BSP::GSM::A7670E::RESPONSE_SIZE bytes to keep the information lines; the buffer is NUL-terminated and separates the lines with '
    '.
  • A command sent while the modem is off or asleep returns NOT_READY without touching the port.

void identify() {
if (!modem.power().on()) {
return;
}
// The information lines of 'ATI' (manufacturer, model, revision) are kept in the buffer.
std::array<char, Modem::RESPONSE_SIZE> response{};
if (modem.sendCommand("ATI", response, std::chrono::milliseconds{1000}) == Modem::Result::OK) {
// 'response' now holds the lines, for example to log them or to check the model name.
}
modem.power().off();
}

Registration, signal, time and location

The network group waits for the registration, then reads the signal strength, the clock and the cell position. Each query returns std::nullopt when the modem did not answer.

  • Lib::BSP::GSM::A7670E::Network::setLTEOnly() restricts the radio to LTE, so the attach does not scan 2G and 3G.
  • Lib::BSP::GSM::A7670E::Network::waitForRegistration() returns false early when the network denies the registration.
  • Lib::BSP::GSM::A7670E::Network::getLocation() uses a little mobile data and needs an active data context.

void readNetwork() {
if (!modem.power().on()) {
return;
}
static_cast<void>(modem.network().setLTEOnly());
if (modem.network().waitForRegistration(std::chrono::seconds{60})) {
const std::optional<uint8_t> signal = modem.network().getSignalQuality(); // 0..31, see the getter
const std::optional<uint32_t> utc = modem.network().getTime(); // Seconds since 1970 in UTC
const std::optional<Modem::Location> position = modem.network().getLocation();
if (signal && utc && position) {
// Use the values here, for example to build the report.
}
}
modem.power().off();
}

UART sleep and wake

Lib::BSP::GSM::A7670E::Power::sleep() puts the modem into UART sleep and raises DTR. The modem stays registered on the network, but every command returns NOT_READY until Lib::BSP::GSM::A7670E::Power::wakeUp() drives DTR low again and confirms the modem answers.

  • Sleep needs the DTR pin in the configuration; without it Lib::BSP::GSM::A7670E::Power::sleep() returns false.
  • Lib::BSP::GSM::A7670E::Power::off() wakes a sleeping modem before it detaches.
#include <Lib/BSP/GSM/A7670E.hpp>

#include <Lib/HAL/UART/StreamSerialPort.hpp>

constexpr Lib::HAL::GPIO::Handle RESET_PIN = PIN(MODEM_RESET);

constexpr Lib::HAL::GPIO::Handle DTR_PIN = PIN(MODEM_DTR);
constexpr Lib::HAL::GPIO::Handle SUPPLY_PIN = PIN(MODEM_SUPPLY_EN);
Lib::HAL::StreamSerialPort port{{.handle = &huart3, .bufferSize = 512U}};
Lib::HAL::GPIO::Output powerKey{POWER_KEY_PIN};
Lib::HAL::GPIO::Output reset{RESET_PIN};
Lib::HAL::GPIO::Input status{STATUS_PIN};
Lib::HAL::GPIO::Output dtr{DTR_PIN};
Lib::HAL::GPIO::Output supplyEnable{SUPPLY_PIN};

void sleepUntilNextReport() {
if (!modem.power().on()) {
return;
}
if (!modem.power().sleep()) {
modem.power().off(); // Sleep was refused, so the modem stays awake and is simply switched off.
return;
}
// Wait for the next report period with the application's own timer; the modem is asleep meanwhile.
if (!modem.power().wakeUp()) {
modem.power().off();
return;
}
modem.power().off();
}

Whole-file write and read

Lib::BSP::GSM::A7670E::Files::write() stores a file under a temporary name and renames it, so a power loss does not lose both copies. Lib::BSP::GSM::A7670E::Files::read() fills a buffer from the start of the file and returns the number of bytes read.

  • A missing file makes Lib::BSP::GSM::A7670E::Files::read() return 0; Lib::BSP::GSM::A7670E::Files::exists() tells a missing file from a failed query.
  • Paths are full, such as 'C:/settings.bin', and the modem refuses wildcards and subdirectories.
  • Both calls fail while a Lib::BSP::GSM::A7670E::File is open, because the modem has one file handle for the driver.

void storeSetting() {
if (!modem.power().on()) {
return;
}
constexpr std::string_view PATH = "C:/settings.bin";
const std::array<uint8_t, 4U> settings{1U, 2U, 3U, 4U};
std::array<uint8_t, 4U> stored{};
// Write only when the content differs, because every write wears the modem flash.
if ((modem.files().read(PATH, stored) != stored.size()) || (stored != settings)) {
if (!modem.files().write(PATH, settings)) {
// The modem refused the write; keep the setting in RAM for this session.
}
}
modem.power().off();
}

Handle-based file access

Lib::BSP::GSM::A7670E::File is worth using when a file is too large to hold in RAM or when only part of it changes. It opens with a mode, moves with Lib::BSP::GSM::A7670E::File::seek(), and closes when it goes out of scope.

  • Lib::BSP::GSM::A7670E::File::read() returns 0 both at the end of the file and on an error.
  • APPEND positions the file at its end when it opens, so every write adds a record.
  • Only one Lib::BSP::GSM::A7670E::File can be open at a time.

void logAndReadBack() {
if (!modem.power().on()) {
return;
}
// Append a record to the end of the log.
const std::array<uint8_t, 4U> record{1U, 2U, 3U, 4U};
{
Modem::File log{modem};
if (log.open("C:/log.bin", Modem::File::Mode::APPEND) && log.write(record)) {
// The record is in the modem flash.
}
}
// Read 16 bytes starting at offset 4.
std::array<uint8_t, 16U> buffer{};
Modem::File file{modem};
if (file.open("C:/log.bin", Modem::File::Mode::READ) && file.seek(4, Modem::File::Origin::BEGIN)) {
const size_t count = file.read(buffer); // 0 at the end of the file or on an error
static_cast<void>(count);
}
modem.power().off();
}
