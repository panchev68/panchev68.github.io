Lib::HAL::UARTPort

Sends and receives bytes with 'Lib::HAL::UARTPort' in its three transfer modes: Lib::HAL::DriverMode::BLOCKING, Lib::HAL::DriverMode::IT and Lib::HAL::DriverMode::DMA.

Sends and receives bytes with 'Lib::HAL::UARTPort' in its three transfer modes: Lib::HAL::DriverMode::BLOCKING, Lib::HAL::DriverMode::IT and Lib::HAL::DriverMode::DMA. The port wraps a CubeMX 'UART_HandleTypeDef' and does not create or configure the pins, clock or NVIC; the CubeMX-generated init code does that.

The blocking mode completes inside the HAL call and may be used from any task. The IT and DMA modes start the transfer and wait on an RTOS::EventGroup, so 'Lib::HAL::UARTPort::send()' and 'Lib::HAL::UARTPort::receive()' are task-only; they assert when called from an ISR. The HAL callbacks that report completion run in interrupt context, and the USART interrupt handler (CubeMX 'USART2_IRQHandler()') must call HAL_UART_IRQHandler() for the handle.

Warning
The IT and DMA ports register their own HAL callbacks in 'Lib::HAL::UARTPort::open()', so the HAL configuration header must set 'USE_HAL_UART_REGISTER_CALLBACKS' to 1; otherwise the build stops with a compile-time error.

Usage

Setup and lifecycle

The CubeMX init code creates the handle ('huart2' in the examples below) and the interrupt. The port does not own the handle, so it must outlive the port. 'Lib::HAL::UARTPort::open()' runs HAL_UART_Init() and, for the IT and DMA modes, registers the callbacks and creates the event group; it returns false on failure. 'Lib::HAL::UARTPort::close()' reverses this and must be called from task context. The destructor of the IT and DMA modes closes an open port.

The BLOCKING specialization is different: its constructor takes a 'Lib::HAL::DriverDataDirection' tag ('RX' or 'TX') that only labels the half of a duplex link the instance drives, and it has no event group, so it needs no open() before use.

Blocking transfers

'Lib::HAL::UARTPort::send()' and 'Lib::HAL::UARTPort::receive()' take a 'std::span' and a timeout in any std::chrono duration. The buffer size must be between 1 and 65535 bytes. Both return false on error or timeout.

#include <Lib/HAL/UART.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern UART_HandleTypeDef huart2;
bool exchangeBlocking() noexcept {
Lib::HAL::UARTPort<Lib::HAL::DriverMode::BLOCKING> txPort(&huart2, Lib::HAL::DriverDataDirection::TX);
Lib::HAL::UARTPort<Lib::HAL::DriverMode::BLOCKING> rxPort(&huart2, Lib::HAL::DriverDataDirection::RX);
const std::array<uint8_t, 4> request{0x01U, 0x02U, 0x03U, 0x04U};
if (!txPort.send(request, std::chrono::milliseconds(100))) {
return false;
}
std::array<uint8_t, 8> response{};
return rxPort.receive(response, std::chrono::milliseconds(200));
}

Interrupt-driven transfers

Open the port once from a task. The CubeMX 'USART2_IRQHandler()' is the only hook needed: it calls 'HAL_UART_IRQHandler(&huart2)', which in turn fires the callbacks that 'Lib::HAL::UARTPort::open()' registered. Transmit and receive use separate event bits, so one task may send while another receives on the same port.

#include <Lib/HAL/UART.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern UART_HandleTypeDef huart2;
class SerialLink final {
public:
SerialLink() noexcept :
port(&huart2) {
}
// Call from a task; opens the port and runs HAL_UART_Init().
bool start() noexcept {
return port.open();
}
// Call from a task only.
bool query() noexcept {
const std::array<uint8_t, 2> command{0xAAU, 0x55U};
if (!port.send(command, std::chrono::milliseconds(50))) {
return false;
}
return port.receive(reply, std::chrono::milliseconds(50));
}
private:
Lib::HAL::UARTPort<Lib::HAL::DriverMode::IT> port;
std::array<uint8_t, 4> reply{};
};

Error path and abort

When a transfer times out or the HAL reports an error, 'Lib::HAL::UARTPort::send()' and 'Lib::HAL::UARTPort::receive()' abort that direction before they return false, so the HAL never touches the caller's buffer afterwards. A task blocked in one of them can be released from another task by 'Lib::HAL::UARTPort::abort()', which returns false if the hardware did not stop cleanly. 'Lib::HAL::UARTPort::setBaudRate()' returns false while a transfer is in flight, so stop or wait for the transfer first.

#include <Lib/HAL/UART.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern UART_HandleTypeDef huart2;
void recoverAndRetune(Lib::HAL::UARTPort<Lib::HAL::DriverMode::IT> & port) noexcept {
if (!port.setBaudRate(115200U)) {
static_cast<void>(port.abort());
static_cast<void>(port.setBaudRate(115200U));
}
}

DMA transfers

The DMA mode has the same API as the IT mode. The CubeMX code must link the UART handle to its DMA handles and enable the DMA interrupts. The buffer must stay valid until the transfer completes, and it must be reachable by the DMA controller (not CCM RAM); a debug build asserts on a CCM buffer.

#include <Lib/HAL/UART.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern UART_HandleTypeDef huart2;
// Static storage in normal RAM, so the DMA controller can reach it.
static std::array<uint8_t, 64> dmaTxBuffer{};
bool sendDma(Lib::HAL::UARTPort<Lib::HAL::DriverMode::DMA> & port, size_t length) noexcept {
return port.send(std::span<const uint8_t>(dmaTxBuffer).first(length), std::chrono::milliseconds(100));
}
