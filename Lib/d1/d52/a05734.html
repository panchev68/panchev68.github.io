Lib::Helper::Delayfinal

Description

Busy-wait delay helpers based on the ARM Cortex-M Data Watchpoint and Trace (DWT) cycle counter.

Suitable for short, precise delays where suspending the task or using RTOS timers would be too coarse. Every delay is rounded up to whole CPU cycles, so it is never shorter than requested; interrupts may lengthen it. The microsecond path and its helpers carry 'pragma inline=forced': measured on a 16 MHz Cortex-M33 with optimization off (a Debug build, where asserts/breakpoints in a caller like a 1-Wire bit-bang driver are actually live), the un-inlined call chain added roughly 100 extra cycles (over 6 us) on top of the requested wait - enough by itself to corrupt a protocol slot a few microseconds wide. Forcing the inline keeps that overhead low independent of the build's optimization level.

◆ microseconds() [2/2]

void Lib::Helper::Delay::microseconds ( uint32_t us)
inlinestaticnoexcept

Delays execution for the specified number of microseconds.

Bypasses the generic nanosecond-based conversion below ('waitFor()' and 'toCycles()'): that path needs a 64-bit division, measured at roughly 600 CPU cycles on a 16 MHz Cortex-M33 - more than six times the 6 us it was meant to wait for, which is fatal to a tight bit-bang slot (e.g. 1-Wire). This path only ever divides two 32-bit values ('SystemCoreClock' by the constant 1'000'000), a single hardware 'UDIV', then multiplies by 'us' - correct for any clock that is a whole number of MHz (every STM32 configuration in practice), with the same 'never shorter than requested' guarantee.
