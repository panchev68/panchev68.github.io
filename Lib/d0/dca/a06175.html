Lib::HAL::DACPort

Drives a DAC output channel through Lib::HAL::DACPort in three modes: 'Lib::HAL::DriverMode::BLOCKING' sets a static level, 'Lib::HAL::DriverMode::IT' adds the channel underrun interrupt, and 'Lib::HAL::DriverMode::DMA' plays a circular waveform from a caller-owned buffer.

Drives a DAC output channel through Lib::HAL::DACPort in three modes: 'Lib::HAL::DriverMode::BLOCKING' sets a static level, 'Lib::HAL::DriverMode::IT' adds the channel underrun interrupt, and 'Lib::HAL::DriverMode::DMA' plays a circular waveform from a caller-owned buffer. The port wraps a DAC_HandleTypeDef created by CubeMX and takes the channel as a constructor argument; the output pin and any hardware trigger are configured by CubeMX.

The IT and DMA modes need USE_HAL_DAC_REGISTER_CALLBACKS set to 1 in the HAL configuration header, otherwise the header stops the build with a compile-time error. Their waiting functions, Lib::HAL::DACPort::waitForUnderrun() and Lib::HAL::DACPort::waitForEvent(), block the calling task and must not run in an ISR.

Hardware assumptions

  • The DAC handle is generated by CubeMX (for example hdac, declared in 'dac.c'); the channel is DAC_CHANNEL_1 or DAC_CHANNEL_2.
  • The IT and DMA modes depend on the interrupts CubeMX assigns: the DAC interrupt forwards to HAL_DAC_IRQHandler() from TIM6_DAC_IRQHandler(), and the DMA stream forwards to HAL_DMA_IRQHandler().
  • With a hardware trigger configured, the value written by Lib::HAL::DACPortBase::setValue() reaches the output on the next trigger edge, not immediately.

Static level

Lib::HAL::DACPort::start() enables the channel, Lib::HAL::DACPortBase::setValue() writes the output register, and the destructor stops the channel. Without a hardware trigger the value reaches the pin during the call itself.

#include <Lib/HAL/DAC/DACPort-Block.hpp>
#include <cstdint>
extern DAC_HandleTypeDef hdac;
void setLevelBlocking() noexcept {
Lib::HAL::DACPort<Lib::HAL::DriverMode::BLOCKING> dac(&hdac, DAC_CHANNEL_1);
if (!dac.start()) {
return;
}
static_cast<void>(dac.setValue(2048U)); // Half of the 12-bit range.
}

Underrun monitoring

In the IT mode Lib::HAL::DACPort::start() clears stale underrun events, starts the channel and then enables the underrun interrupt. The DAC reports Lib::HAL::DACPort::Event::UNDERRUN only when a trigger arrives while the previous DMA request was not served; it does not signal that a value reached the output. Lib::HAL::DACPort::waitForUnderrun() returns true when an underrun was reported before the timeout, and consumes the event.

#include <Lib/HAL/DAC/DACPort-IT.hpp>
#include <RTOS.hpp>
#include <cassert>
#include <chrono>
#include <cstdint>
extern DAC_HandleTypeDef hdac;
class DacMonitor final {
public:
DacMonitor() noexcept :
dac(&hdac, DAC_CHANNEL_1),
task(RTOS::Task::Config("DacMon", 256, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::DACPort<Lib::HAL::DriverMode::IT> dac;
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!dac.open() || !dac.start()) {
assert(!"DacMonitor: failed to open or start DAC");
return;
}
static_cast<void>(dac.setValue(1024U));
while (true) {
if (dac.waitForUnderrun(std::chrono::milliseconds(500))) {
// Underrun: the trigger outran the DMA request. Log it.
}
}
}
};

Circular waveform

Lib::HAL::DACPort::start() hands the waveform buffer to DMA, which repeats it until Lib::HAL::DACPort::stop() is called. The buffer must stay valid for that whole time, so keep it static or otherwise outliving the output. Each sample is a 32-bit word whose value is aligned as given by Lib::HAL::DACPortBase::DataAlignment. The DMA mode reports Lib::HAL::DACPort::waitForEvent() bits, one per callback ID, such as HAL_DAC_CH1_COMPLETE_CB_ID.

#include <Lib/HAL/DAC/DACPort-DMA.hpp>
#include <RTOS.hpp>
#include <array>
#include <chrono>
#include <cmath>
#include <cstddef>
#include <cstdint>
#include <span>
extern DAC_HandleTypeDef hdac;
void playSineLoop() noexcept {
static std::array<uint32_t, 64> waveform{};
for (std::size_t i = 0; i < waveform.size(); ++i) {
const float angle = 2.0F * 3.14159265F * static_cast<float>(i) / static_cast<float>(waveform.size());
waveform[i] = static_cast<uint32_t>(2048.0F + 2000.0F * std::sin(angle));
}
Lib::HAL::DACPort<Lib::HAL::DriverMode::DMA> dac(&hdac, DAC_CHANNEL_1);
if (!dac.open()) {
return;
}
if (dac.start(std::span<const uint32_t>(waveform), Lib::HAL::DACPort<Lib::HAL::DriverMode::DMA>::DataAlignment::RIGHT_12_BITS)) {
const auto events = dac.waitForEvent(HAL_DAC_CH1_COMPLETE_CB_ID, std::chrono::milliseconds(100));
if (events.any()) {
// One full pass of the waveform was output.
}
static_cast<void>(dac.stop());
}
static_cast<void>(dac.close());
}

Error path

In the IT and DMA modes a failed Lib::HAL::DACPort::open() rolls back the steps it already completed, so the port is left closed. Lib::HAL::DACPort::start() and Lib::HAL::DACPort::stop() return false when the HAL call fails. A DMA Lib::HAL::DACPort::start() with an empty buffer, or before Lib::HAL::DACPort::open(), trips an assert in debug builds, so check the result of open() before starting.

#include <Lib/HAL/DAC/DACPort-DMA.hpp>
#include <cstdint>
#include <span>
bool startWaveform(Lib::HAL::DACPort<Lib::HAL::DriverMode::DMA> & dac, std::span<const uint32_t> waveform) noexcept {
if (!dac.open()) {
return false; // The port is left closed.
}
if (!dac.start(waveform, Lib::HAL::DACPort<Lib::HAL::DriverMode::DMA>::DataAlignment::RIGHT_12_BITS)) {
static_cast<void>(dac.close());
return false;
}
return true;
}
