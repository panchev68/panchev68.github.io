Description

template<typename T_DERIVED = void>
class Lib::BSP::RFID::MFRC522< T_DERIVED >

Driver for the MFRC522 RFID reader connected over SPI, dispatched through CRTP instead of virtual calls.

Manages hardware initialization, antenna control and a background polling task that detects cards and reports their UID. Every detected UID is routed through handleCardDetected(); its default implementation forwards to the callback bound via bindCardDetectionCallback(). A class deriving from 'MFRC522<T_DERIVED>' passes itself as 'T_DERIVED' and overrides handleCardDetected() to react without going through the callback. The static_cast to 'Self' in 'taskEntry()' selects that override.

Template Parameters
T_DERIVEDConcrete driver overriding handleCardDetected(), or 'void' to use MFRC522 directly without an override.

◆ handleCardDetected()

template<typename T_DERIVED = void>
void Lib::BSP::RFID::MFRC522< T_DERIVED >::handleCardDetected ( std::span< const uint8_t > uid)
inlinenoexcept

Handles a detected card's UID; bound as the polling task's per-card dispatch point.

This default implementation forwards to the callback bound via bindCardDetectionCallback(), if any. 'T_DERIVED' overrides it to react without going through the callback. Not meant to be called directly.

The callback reference is snapshotted under a critical section, so a rebind from another task via bindCardDetectionCallback() cannot race with this read. The callback itself is invoked outside the guard, so an arbitrary-length user callback never runs with interrupts disabled.

Parameters
uidDetected UID; valid only for the duration of the call.
