Lib::Helper::RingBuffer

Passes samples from a producer context to a consumer context with Lib::Helper::RingBuffer.

Passes samples from a producer context to a consumer context with Lib::Helper::RingBuffer. The buffer is lock-free and safe only with one producer (for example an interrupt handler) and one consumer (for example a task). Lib::Helper::RingBuffer::overwrite() advances the read side and must not run concurrently with Lib::Helper::RingBuffer::pop() or with consumer-side reads.

Single element transfer

The producer calls Lib::Helper::RingBuffer::push() from the interrupt handler and the consumer calls Lib::Helper::RingBuffer::pop() from a task. A full buffer makes Lib::Helper::RingBuffer::push() return false, so the sample is dropped and the caller decides what to do with it.

#include <Lib/Helper/RingBuffer.hpp>
#include <cstdint>
Lib::Helper::RingBuffer<uint16_t, 32U> samples;
// Producer: called from the ADC conversion-complete interrupt.
void onSample(uint16_t value) noexcept {
if (!samples.push(value)) {
// Buffer full: the newest sample is dropped.
}
}
// Consumer: called from a task.
void consumeOne() noexcept {
uint16_t value = 0U;
if (samples.pop(value)) {
// Use value.
}
}

Bulk transfer with a transfer mode

Lib::Helper::RingBuffer::write() and Lib::Helper::RingBuffer::read() move several elements at once. Lib::Helper::RingBuffer::TransferMode::PARTIAL transfers as many elements as fit or are available; Lib::Helper::RingBuffer::TransferMode::ALL transfers nothing unless the whole request can be served.

#include <Lib/Helper/RingBuffer.hpp>
#include <array>
#include <cstdint>
#include <span>
Lib::Helper::RingBuffer<uint8_t, 64U> rxBuffer;
void bulkExample() noexcept {
const std::array<uint8_t, 4U> frame{0x01U, 0x02U, 0x03U, 0x04U};
const size_t written = rxBuffer.write(frame, Lib::Helper::RingBuffer<uint8_t, 64U>::TransferMode::ALL);
if (written == 0U) {
// Not enough free space for the whole frame; nothing was written.
}
std::array<uint8_t, 16U> chunk{};
const size_t readCount = rxBuffer.read(chunk, Lib::Helper::RingBuffer<uint8_t, 64U>::TransferMode::PARTIAL);
[[maybe_unused]] const std::span<const uint8_t> received(chunk.data(), readCount);
}

Direct access for DMA

A DMA controller can write into the free span returned by Lib::Helper::RingBuffer::getLinearWriteBlock() and read from the stored span returned by Lib::Helper::RingBuffer::getLinearReadBlock(). The caller publishes the elements afterwards with Lib::Helper::RingBuffer::advance() and Lib::Helper::RingBuffer::skip(). Each span may be shorter than the total free or stored space when the data wraps past the end of the storage, so call again to reach the remainder.

#include <Lib/Helper/RingBuffer.hpp>
#include <cstdint>
#include <span>
Lib::Helper::RingBuffer<uint8_t, 256U> dmaBuffer;
void dmaReceiveDone(size_t receivedBytes) noexcept {
// The DMA wrote into the span returned by getLinearWriteBlock() before this call.
[[maybe_unused]] const size_t published = dmaBuffer.advance(receivedBytes);
}
void dmaTransmitFrom() noexcept {
const std::span<const uint8_t> block = dmaBuffer.getLinearReadBlock();
// Start a DMA transfer from block.data() with block.size() bytes, then call skip() when it completes.
}

Keeping the latest samples

When only the most recent samples matter, Lib::Helper::RingBuffer::overwrite() discards the oldest elements to make room. Call it only from the producer side and only when no consumer reads at the same time.

#include <Lib/Helper/RingBuffer.hpp>
#include <array>
#include <cstdint>
#include <span>
Lib::Helper::RingBuffer<int16_t, 8U> window;
void keepLatest() noexcept {
const std::array<int16_t, 3U> batch{10, 20, 30};
[[maybe_unused]] const size_t accepted = window.overwrite(batch);
// The window now holds the newest elements, at most CAPACITY of them.
}
