Lib::BSP::EEPROM::FlashEmulationfinal

Description

Stores 16-bit keyed records in two erasable flash pages, appended as a log and compacted when a page fills up.

Every record is a 16-byte header followed by its data, padded to a multiple of 16 bytes, because the STM32U5 programs flash in quadwords. The data is written first and the header last, so a power loss leaves an erased header and the record is simply absent. The newest record of a key wins. A page holds a 16-byte page header with a sequence number, written last during compaction, so the page with the higher sequence is the active one. Reads go straight to the memory-mapped flash; writes and erases use the HAL.

Access is by key, not by address: compaction moves the live records, so an offset would not stay valid. Each key has its own length, from 1 to 'MAX_VALUE_SIZE' bytes, stored in its record header; a new value of a different length simply replaces the old one. A value equal to the stored one is not written again.

Each write of a changed value consumes flash space. When the active page is full, the latest value of every key is copied to the other page, and the old page is erased before the next compaction reuses it. The live values of all keys together must fit into one page; dead records do not count, because compaction drops them.

Warning
Erasing and programming stall the CPU while code in the same flash bank is fetched. Keep the emulated pages in a bank that holds no code; the two pages of the last sector pair of bank 2 are a suitable choice.
Call only from task context: the HAL polls the flash until each operation completes.
Important
The linker script must not place code or constants in the emulated pages. Lower the end of the ROM region below the base address, e.g. 'ICFEDIT_region_ROM_end = 0x081FBFFF' for base 0x081FC000.

◆ getFreeSpace()

size_t Lib::BSP::EEPROM::FlashEmulation::getFreeSpace ( )
inlinenodiscardnoexcept

Gets the bytes that can still be appended to the active page without a compaction.

Dead records are not reclaimed here, so this value only falls until the next compaction. A damaged record at the end of the page makes the page unclean; then the space is reported as 0, because new records are refused until compaction.

Returns
Free bytes of the active page, or 0 if the area is not open.

◆ getUsedSpace()

size_t Lib::BSP::EEPROM::FlashEmulation::getUsedSpace ( )
inlinenodiscardnoexcept

Gets the bytes occupied by records in the active page, including dead ones.

The value counts every appended record, so it grows with each changed write until compaction copies the live values to the other page and drops the rest. The live values alone are usually smaller.

Returns
Used bytes of the active page, or 0 if the area is not open.
