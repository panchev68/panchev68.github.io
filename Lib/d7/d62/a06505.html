Lib::Math::Filter::ExponentialSmoothing

Smooths a slow signal with Lib::Math::Filter::ExponentialSmoothing, a first-order low-pass filter: every sample moves the output a fixed fraction towards itself.

Smooths a slow signal with Lib::Math::Filter::ExponentialSmoothing, a first-order low-pass filter: every sample moves the output a fixed fraction towards itself. It keeps one value and no sample memory, so heavy smoothing costs no buffer, which suits a temperature shown on a display. It does not reject a single wild sample, which only fades away over many samples. The filter is not thread-safe, so call it from one context only.

Configuration

The smoothing constant alpha is greater than 0 and at most 1: a small value gives a slow, smooth output and 1 passes the input unchanged. Lib::Math::Filter::ExponentialSmoothing::getAlphaForSamples() gives the constant that settles in about the given number of samples. The first sample sets the output directly, so there is no start-up ramp from zero.

#include <Lib/Math/Filter/ExponentialSmoothing.hpp>
#include <cstdint>
using DisplayFilter = Lib::Math::Filter::ExponentialSmoothing<int16_t>;
// Temperature in 0.1 degC, smoothed over about 40 readings.
DisplayFilter displayFilter({.alpha = DisplayFilter::getAlphaForSamples(40U)});
// Called from the task that receives the thermometer readings.
int16_t onReading(int16_t reading) noexcept {
return displayFilter(reading);
}

Integral samples

The state is kept in float for an integral sample type and the result is rounded to the nearest integer. With alpha = 0.5 the output halves its distance to the input on every sample.

#include <Lib/Math/Filter/ExponentialSmoothing.hpp>
#include <cstdint>
Lib::Math::Filter::ExponentialSmoothing<int> filter({.alpha = 0.5F});
int onSample(int sample) noexcept {
return filter(sample);
}

Changing the constant and resetting

Lib::Math::Filter::ExponentialSmoothing::setAlpha() changes the constant and keeps the running output, for example to follow a change faster for a while. Lib::Math::Filter::ExponentialSmoothing::reset() forgets the output, so the next sample sets it directly. Lib::Math::Filter::ExponentialSmoothing::hasValue() tells whether an output exists.

#include <Lib/Math/Filter/ExponentialSmoothing.hpp>
Lib::Math::Filter::ExponentialSmoothing<float> filter;
void followFast() noexcept {
filter.setAlpha(0.5F);
}
void onLinkLost() noexcept {
filter.reset();
}
bool isOutputValid() noexcept {
return filter.hasValue();
}

Removing spikes first

A spike fades away only slowly. Put a Lib::Math::Filter::Median in front of the filter to drop it first.

#include <Lib/Math/Filter/ExponentialSmoothing.hpp>
#include <Lib/Math/Filter/Median.hpp>
#include <cstdint>
Lib::Math::Filter::Median<int16_t, 5U> spikeFilter;
Lib::Math::Filter::ExponentialSmoothing<int16_t> displayFilter({.alpha = 0.05F});
int16_t onReading(int16_t reading) noexcept {
return displayFilter(spikeFilter(reading));
}
