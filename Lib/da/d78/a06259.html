RTOS::MutexGuard

Shows scope-based locking with RTOS::MutexGuard, which unlocks the mutex automatically when the guard leaves scope.

Shows scope-based locking with RTOS::MutexGuard, which unlocks the mutex automatically when the guard leaves scope. It covers an indefinite lock and a timed lock, and checks the guard state after construction.

The example runs in a task context with the FreeRTOS scheduler running. A mutex must never be locked or unlocked from an ISR. The first guard blocks indefinitely, because it uses the default RTOS::Mutex::WAIT_FOREVER timeout.

Scoped lock with an indefinite wait

#include <Lib/RTOS/FreeRTOS/Mutex.hpp>
#include <Lib/RTOS/FreeRTOS/MutexGuard.hpp>
void lockedSection() {
RTOS::Mutex mutex(RTOS::Mutex::Type::NORMAL);
if (!mutex.open()) {
return; // Creation failed: out of heap.
}
{
const RTOS::MutexGuard guard(mutex); // Locks on construction, waits forever.
if (guard.isLocked()) {
// Critical section protected by 'mutex'.
}
} // Guard destroyed here; the mutex is unlocked only if it was locked.
mutex.close();
}

Timed lock

The guard converts the std::chrono::duration to ticks. When the lock times out, the critical section is not protected and nothing is unlocked.

#include <Lib/RTOS/FreeRTOS/Mutex.hpp>
#include <Lib/RTOS/FreeRTOS/MutexGuard.hpp>
#include <chrono>
using namespace std::chrono_literals;
void timedSection(RTOS::Mutex & mutex) {
if (const RTOS::MutexGuard guard(mutex, 10ms); guard) {
// Lock acquired within 10 ms.
} else {
// Timed out: the critical section is not protected.
}
}
