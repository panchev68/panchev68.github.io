Lib::HAL::StreamSerialPort

Reads a UART byte stream with Lib::HAL::StreamSerialPort, which receives one byte at a time in an interrupt and pushes it into an RTOS::StreamBuffer that one task reads.

Reads a UART byte stream with Lib::HAL::StreamSerialPort, which receives one byte at a time in an interrupt and pushes it into an RTOS::StreamBuffer that one task reads. Writes are blocking. The port wraps a CubeMX 'UART_HandleTypeDef' and does not configure the pins or the clock.

Only one task may call Lib::HAL::StreamSerialPort::read() and Lib::HAL::StreamSerialPort::discardInput(); the stream buffer has a single reader. Lib::HAL::StreamSerialPort::write() is blocking and may be called from task context only. Up to four ports may be open at the same time, because the interrupt callback looks the port up by its handle.

Important
The class is compiled only when 'HAL_UART_MODULE_ENABLED' is defined in the HAL configuration header. That header is not part of this repository, so the guard is unverified here; on STM32F407 the UART module is available on the target.

Usage

Construction and lifecycle

The 'Config' struct takes the CubeMX handle and the receive capacity in bytes. The constructor does not touch the hardware; Lib::HAL::StreamSerialPort::open() initializes the UART when it is still in the reset state, allocates the stream once, and arms the first one-byte reception. It returns true when the port is already open. Lib::HAL::StreamSerialPort::close() aborts the reception and de-initializes the UART, so its pins return to the analog state and a powered-down device is not back-fed through TX. The destructor closes an open port.

The CubeMX init must set 'USE_HAL_UART_REGISTER_CALLBACKS' to 1, because the port registers its own RX-complete and error callbacks.

Interrupt hook

No application code runs in the interrupt. The CubeMX 'USART2_IRQHandler()' must call HAL_UART_IRQHandler() for the handle, which fires the callbacks registered by Lib::HAL::StreamSerialPort::open(). Each received byte is sent to the stream from the interrupt context and a yield is requested when a higher-priority task woke up. A byte that does not fit is counted and can be read back with Lib::HAL::StreamSerialPort::getDroppedCount().

Reading a frame

Lib::HAL::StreamSerialPort::read() copies up to the size of the span and returns the number of bytes received. It returns 0 on timeout or while the port is closed, so a caller that expects a frame loops until it has collected enough bytes or a deadline passed.

#include <Lib/HAL/UART/StreamSerialPort.hpp>
#include <array>
#include <chrono>
#include <cstddef>
#include <cstdint>
#include <string_view>
extern UART_HandleTypeDef huart2;
class ModemReader final {
public:
ModemReader() noexcept :
port({
.handle = &huart2,
.bufferSize = 256U,
}) {
}
// Call from the single reader task.
bool start() noexcept {
return port.open();
}
// Call from the single reader task only; returns the number of bytes stored in 'frame'.
size_t readFrame(std::span<uint8_t> frame) noexcept {
size_t total = 0U;
const auto deadline = std::chrono::steady_clock::now() + std::chrono::milliseconds(500);
while ((total < frame.size()) && (std::chrono::steady_clock::now() < deadline)) {
total += port.read(frame.subspan(total), std::chrono::milliseconds(20));
}
return total;
}
private:
Lib::HAL::StreamSerialPort port;
};

Writing and resynchronizing

Lib::HAL::StreamSerialPort::write() accepts a byte span or a std::string_view and returns true only when every byte was sent. Before a new exchange, Lib::HAL::StreamSerialPort::discardInput() drops bytes left from an earlier, unanswered message.

#include <Lib/HAL/UART/StreamSerialPort.hpp>
#include <chrono>
#include <string_view>
bool sendCommand(Lib::HAL::StreamSerialPort & port) noexcept {
port.discardInput();
return port.write(std::string_view("AT\r\n"), std::chrono::milliseconds(100));
}
