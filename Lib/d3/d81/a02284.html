Description

template<HttpTransport T_TRANSPORT>
class Lib::HTTP::Client< T_TRANSPORT >

Transport-agnostic HTTP/1.1 client.

Builds a request line and headers by hand (no heap, no exceptions) and sends it, followed by an optional body, over the given "HttpTransport"; then reads the response into a caller-provided buffer. Only 'Content-Length'-delimited responses are understood - chunked transfer encoding is not supported, which is fine for the JSON responses typical of a cloud REST API but not for arbitrary HTTP servers. Each request sends 'Connection: close' and expects the transport/connection to be torn down and re-established by the caller between requests.

For plain HTTP, "T_TRANSPORT" is whatever already-connected byte-stream type the project uses (e.g. a Wiznet "Socket", a GSM module's data-mode stream, ...) as long as it satisfies "HttpTransport" directly - no dedicated plain-TCP adapter is provided here, since the shape is already what most transports expose. For HTTPS, wrap that same transport in "WolfSSLTransport<T_RAW_TRANSPORT>".

Template Parameters
T_TRANSPORTTransport type satisfying "HttpTransport", e.g. the project's own socket/stream type or "WolfSSLTransport<T_RAW_TRANSPORT>".
