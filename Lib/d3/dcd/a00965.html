Lib::Canbus::Service< Mode::CLIENT >abstract

Description

CAN bus client service specialization.

This class implements the base functionality required for CAN bus client services. It provides a standardized interface for sending CAN messages, retrieving diagnostic information, and handling incoming messages and errors. The class is designed as a protected inheritance from ServiceBase to encapsulate CAN-specific operations while allowing derived classes to extend functionality.

Key responsibilities:

  • Initialize and manage CAN communication parameters
  • Send messages with different data formats (raw data, 64-bit values)
  • Provide diagnostic information for service monitoring
  • Handle incoming CAN messages through callbacks
  • Manage service lifecycle (start/stop operations)
  • Define a pure virtual task function for client-specific processing

Derived classes must implement the taskFn() method to provide periodic or event-driven processing logic specific to their client requirements.

Note
This is a template specialization for Mode::CLIENT and cannot be used polymorphically with other service modes.
All public methods are virtual to allow for polymorphic behavior in derived classes.
The class uses protected inheritance to hide ServiceBase implementation details.

Sends a CAN message with custom data.

Parameters
dataPointer to the data buffer to send. Must not be nullptr and must contain valid data. The buffer should not be modified while sending.

timeoutMaximum time in milliseconds to wait for the message to be sent. If 0, the operation will not block. Default is SEND_TIMEOUT.
Returns
true if the message was successfully queued for transmission, false if the send operation failed (e.g., invalid parameters, timeout, bus error).
Precondition
The service must be started and the CAN bus operational.
data must not be nullptr and size must be valid for CAN message constraints.
Postcondition
The message is queued for transmission (success) or an error is logged (failure).
Note
Data is copied into the CAN message; the original buffer can be freed after this call.
If size exceeds CAN payload limits, the message may be truncated or rejected.

virtual void Lib::Canbus::Service< Mode::CLIENT >::taskFn ( )
protectedpure virtual

Client service task function.

Pure virtual function that must be implemented by all derived classes. This method provides the main processing loop for the CAN bus client service, handling periodic tasks, state management, and client-specific logic. It is typically called from an RTOS task or timer interrupt.

Implementation guidelines:

  • Handle periodic operations like status updates or health checks
  • Process received messages and update internal state
  • Implement client-specific protocols or state machines
  • Keep execution time deterministic and bounded
  • Avoid blocking operations that could delay other tasks
Note
This is a pure virtual function; derived classes must provide an implementation.
The function should return promptly to maintain real-time performance.
Use RTOS synchronization primitives if thread-safe operations are needed.
Avoid long-running loops; prefer event-driven processing.
