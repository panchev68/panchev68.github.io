Lib::HAL::CANPort

Sends and receives classic CAN frames through Lib::HAL::CANPort in 'Lib::HAL::DriverMode::BLOCKING' mode, which polls the mailboxes and FIFOs from the calling task, and in 'Lib::HAL::DriverMode::IT' mode, which blocks on task notifications raised from the CAN interrupts.

Sends and receives classic CAN frames through Lib::HAL::CANPort in 'Lib::HAL::DriverMode::BLOCKING' mode, which polls the mailboxes and FIFOs from the calling task, and in 'Lib::HAL::DriverMode::IT' mode, which blocks on task notifications raised from the CAN interrupts. The port wraps a CAN_HandleTypeDef created by CubeMX; the bit timing, the pins and the acceptance filters are set up by CubeMX, and Lib::HAL::CANPort::open() starts the peripheral (in IT mode it also enables the interrupts).

Both modes share Lib::HAL::CANPortBase::write() and Lib::HAL::CANPortBase::read(), which take at most 8 data bytes per frame and never block. The blocking-only helpers Lib::HAL::CANPort::writeBlocking() and Lib::HAL::CANPort::readBlocking() poll with 1 ms task delays and must run in a task, not in an ISR.

Hardware assumptions

  • The CAN handle is generated by CubeMX (for example hcan1, declared in 'can.c'), with its transceiver wired to the CAN pins.
  • The IT mode needs the CAN interrupt lines enabled in the NVIC by CubeMX, so that the HAL can call its callbacks; the port enables the individual interrupt sources itself in Lib::HAL::CANPort::open().
  • The IT mode registers its callbacks with HAL_CAN_RegisterCallback(), which the HAL compiles only when USE_HAL_CAN_REGISTER_CALLBACKS is set to 1 in the HAL configuration header. The port does not check this macro.

Blocking send and receive

Lib::HAL::CANPort::writeBlocking() waits up to its timeout for a free transmit mailbox, and Lib::HAL::CANPort::readBlocking() waits up to its timeout for a pending frame in the chosen FIFO. Both return false on timeout, which is an expected outcome on a quiet bus.

#include <Lib/HAL/CAN/CANPort-Block.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern CAN_HandleTypeDef hcan1;
void exchangeBlocking() noexcept {
Lib::HAL::CANPort<Lib::HAL::DriverMode::BLOCKING> can(&hcan1);
if (!can.open()) {
return;
}
const std::array<uint8_t, 2> status{0x01U, 0x02U};
if (!can.writeBlocking(0x123U, status, std::chrono::milliseconds(10))) {
// No free mailbox within 10 ms.
}
Lib::HAL::CANFrame frame{};
if (can.readBlocking(CAN_RX_FIFO0, frame, std::chrono::milliseconds(100))) {
// Use frame.id, frame.data and frame.length.
}
static_cast<void>(can.close());
}

Interrupt-driven receive task

Lib::HAL::CANPort::open() binds the task that calls it as the notification target, so the task that calls Lib::HAL::CANPort::waitForEvent() must be the one that opened the port. A notification from the CAN interrupts is delivered to that task only.

Warning
Only the task that called Lib::HAL::CANPort::open() may call Lib::HAL::CANPort::waitForEvent(); other tasks never receive the CAN events.

The timeout of Lib::HAL::CANPort::waitForEvent() is in milliseconds, and the call returns the event bits that fired, or 0 on timeout. The port has no error-code getter, so the example closes and reopens the port when ERROR is reported.

#include <Lib/HAL/CAN/CANPort-IT.hpp>
#include <RTOS.hpp>
#include <cassert>
#include <chrono>
#include <cstdint>
extern CAN_HandleTypeDef hcan1;
class CanTask final {
public:
CanTask() noexcept :
can(&hcan1),
task(RTOS::Task::Config("Can", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::CANPort<Lib::HAL::DriverMode::IT> can;
RTOS::Task task; // Must stay the last member.
void run() noexcept {
// open() binds this task, so it must be called here, not from the constructor.
if (!can.open()) {
assert(!"CanTask: failed to open CAN");
return;
}
while (true) {
const uint32_t events = can.waitForEvent(Lib::HAL::CANPort<Lib::HAL::DriverMode::IT>::Event::RX_FIFO0 |
Lib::HAL::CANPort<Lib::HAL::DriverMode::IT>::Event::ERROR,
std::chrono::milliseconds(500));
if ((events & Lib::HAL::CANPort<Lib::HAL::DriverMode::IT>::Event::RX_FIFO0) != 0U) {
Lib::HAL::CANFrame frame{};
// Drain every frame latched in FIFO 0, not just one per notification.
while (can.read(CAN_RX_FIFO0, frame)) {
// Use frame.id, frame.data and frame.length.
}
}
if ((events & Lib::HAL::CANPort<Lib::HAL::DriverMode::IT>::Event::ERROR) != 0U) {
static_cast<void>(can.close());
static_cast<void>(can.open());
}
}
}
};

Transmit with completion

Lib::HAL::CANPortBase::write() returns as soon as a mailbox accepts the frame. The bus transmission completes later, which the IT mode reports as Lib::HAL::CANPort::Event::TX_COMPLETE to the task that opened the port.

#include <Lib/HAL/CAN/CANPort-IT.hpp>
#include <array>
#include <chrono>
#include <cstdint>
void sendWithCompletion(Lib::HAL::CANPort<Lib::HAL::DriverMode::IT> & can) noexcept {
const std::array<uint8_t, 4> payload{0xDEU, 0xADU, 0xBEU, 0xEFU};
if (can.write(0x7FFU, payload)) {
const uint32_t events = can.waitForEvent(Lib::HAL::CANPort<Lib::HAL::DriverMode::IT>::Event::TX_COMPLETE,
std::chrono::milliseconds(10));
static_cast<void>(events);
}
