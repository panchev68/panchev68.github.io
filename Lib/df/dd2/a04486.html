Lib::BSP::Display::SSD1306< T_WIDTH, T_HEIGHT >final

Description

template<size_t T_WIDTH = 128U, size_t T_HEIGHT = 64U>
class Lib::BSP::Display::SSD1306< T_WIDTH, T_HEIGHT >

Monochrome OLED display driven by an SSD1306 controller over I²C, drawn into a RAM frame buffer.

All drawing calls only change the frame buffer; Lib::BSP::Display::SSD1306::flush() sends it to the panel in one transfer. Coordinates start at the top-left corner, x to the right and y downwards, and anything outside the panel is clipped. The I²C port is shared and not guarded here: call the driver from one task, or serialize the callers.

The frame buffer is organized in pages of eight rows: byte x + (y / 8) * T_WIDTH holds the pixel in bit y % 8. It lives inside the object, so a 128 x 64 panel needs 1 KiB of RAM and no heap.

Template Parameters
T_WIDTHPanel width in pixels, 1 to 128.
T_HEIGHTPanel height in pixels, a multiple of 8 from 16 to 64 (typically 64 or 32).

bool Lib::BSP::Display::SSD1306< T_WIDTH, T_HEIGHT >::open ( )
inlinenodiscardnoexcept

Opens the I²C port, initializes the controller and shows a blank screen.

Probes the slave address first. A failed probe leaves the port open, since other devices on the same bus may already use it. The controller is set up for horizontal addressing with the internal charge pump enabled.

Returns
true if the display acknowledged and was initialized, false otherwise.
Examples
Lib::BSP::Display::TouchGFX_BW, and Lib::GUI::Context.
