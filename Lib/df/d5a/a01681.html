RTOS::Mutex

Description

Mutex class for synchronization.

Provides a wrapper around FreeRTOS semaphores for mutex functionality, supporting normal and recursive mutexes. Ensures thread-safe access to shared resources in multi-tasking embedded applications.

The Mutex class encapsulates FreeRTOS semaphore operations to provide:

  • Normal mutexes for basic mutual exclusion
  • Recursive mutexes for nested locking scenarios
  • Timeout-based locking with configurable wait periods
  • Move semantics for efficient resource management
  • RAII-based locking through the LockGuard class

Usage patterns:

  • Use normal mutexes for simple critical sections
  • Use recursive mutexes when a task may need to acquire the same mutex multiple times
  • Use LockGuard for automatic lock management and exception safety
  • Check mutex validity before operations using isValid()
Note
Mutex operations are not ISR-safe; use from tasks only.
Recursive mutexes have higher memory and performance overhead.
Always check FreeRTOS configuration for mutex support.
Attention
Do not use mutexes in ISR contexts; use binary semaphores instead.
Avoid long-held locks to prevent priority inversion and deadlocks.
Examples
RTOS::Mutex, and RTOS::MutexGuard.

Mutex type enumeration.

Defines the type of mutex: normal or recursive. Normal mutexes provide basic mutual exclusion, while recursive mutexes allow the same task to acquire the mutex multiple times without deadlock.

Enumerator
NORMAL 

Normal mutex type. Provides basic mutual exclusion.

RECURSIVE 

Recursive mutex type. Allows nested locking by the same task.

◆ open()

bool RTOS::Mutex::open ( )
inline

Create the mutex.

Allocates and initializes the FreeRTOS semaphore based on the mutex type. This method creates the underlying FreeRTOS semaphore and stores the handle.

Returns
true if creation was successful, false otherwise.
Note
Fails if the mutex is already created or if FreeRTOS configuration doesn't support the mutex type.
For recursive mutexes, configUSE_RECURSIVE_MUTEXES must be 1.
For normal mutexes, configUSE_MUTEXES must be 1.
Attention
Ensure sufficient heap memory is available for semaphore creation.

◆ unlock()

void RTOS::Mutex::unlock ( )
inline

Unlock the mutex.

Releases the mutex, allowing other tasks to acquire it. For recursive mutexes, decrements the lock count.

Note
Safe to call even if mutex is not locked (no-op).
For recursive mutexes, must be called the same number of times as lock().
Attention
Ensure the calling task actually owns the lock.
