Lib::HAL::DeviceManager

Maps a native HAL handle, as seen inside an 'extern "C"' HAL callback, back to the owning C++ object with Lib::HAL::DeviceManager.

Maps a native HAL handle, as seen inside an 'extern "C"' HAL callback, back to the owning C++ object with Lib::HAL::DeviceManager. The objects derive from Lib::HAL::Device, which stores the handle and an intrusive list link.

This is the HAL-side ISR lookup. It is a different class from Lib::BSP::DeviceManager, which holds a periodic timer and a list of BSP drivers; the two share a name but nothing else. The HAL manager is a per-(device type, handle type) singleton, so the template arguments select the instance. Lib::HAL::DeviceManager::registerDevice() and Lib::HAL::DeviceManager::unregisterDevice() take an RTOS critical section. Lib::HAL::DeviceManager::getDevice() does not, which is what lets an ISR call it. The list is searched linearly, so keep the number of instances per type small.

The device registers itself in its constructor and must not be destroyed while an ISR may still look it up: unregister it before it goes away. The example below uses a static instance, so that condition holds.

Derive a device from the base

Derive publicly from Lib::HAL::Device, pass the native handle to its constructor, and register the object with the manager. Lib::HAL::Device::getHandle() returns the handle that the lookup compares against.

#include "stm32f4xx_hal.h" // Declares SPI_HandleTypeDef and the HAL driver.
#include <Lib/HAL/core/Device.hpp>
#include <Lib/HAL/core/DeviceManager.hpp>
#include <cstdint>
extern SPI_HandleTypeDef hspi1; // Generated by CubeMX.
class SpiBridge final : public Lib::HAL::Device<SpiBridge, SPI_HandleTypeDef> {
public:
explicit SpiBridge(SPI_HandleTypeDef * spiHandle) noexcept :
Device(spiHandle) {
static_cast<void>(Lib::HAL::DeviceManager<SpiBridge, SPI_HandleTypeDef>::instance().registerDevice(this));
}
void onTransmitComplete() noexcept {
transmitCount = transmitCount + 1U;
}
private:
volatile uint32_t transmitCount = 0U;
};
static SpiBridge spiBridge(&hspi1);

Look up the owner inside a HAL callback

The callback is defined once, by the application, and only forwards to the device. Defining it replaces the weak HAL definition of the same name, so it must appear only once in the project. A null result means no instance owns that handle, so the callback must simply return. The class from the previous example is assumed to be in 'SpiBridge.hpp'.

#include <Lib/HAL/core/DeviceManager.hpp>
#include "SpiBridge.hpp"
extern "C" void HAL_SPI_TxCpltCallback(SPI_HandleTypeDef * hspi) {
SpiBridge * const bridge = Lib::HAL::DeviceManager<SpiBridge, SPI_HandleTypeDef>::instance().getDevice(hspi);
if (bridge != nullptr) {
bridge->onTransmitComplete();
}
}
