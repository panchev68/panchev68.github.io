Lib::HAL::HASHPort

Computes a SHA-256 digest of a byte buffer with Lib::HAL::HASHPort, in its 'Lib::HAL::DriverMode::BLOCKING' and its 'Lib::HAL::DriverMode::IT' specializations.

Computes a SHA-256 digest of a byte buffer with Lib::HAL::HASHPort, in its 'Lib::HAL::DriverMode::BLOCKING' and its 'Lib::HAL::DriverMode::IT' specializations.Both modes share the lifecycle from Lib::HAL::HASHPortBase: open() initializes the HAL handle and close() de-initializes it. The handle is CubeMX-generated, must stay valid for the lifetime of the port, and must use HASH_DATATYPE_8B, because byte-stream hashing asserts it. The BLOCKING mode polls the peripheral in the calling task. The IT mode waits on an RTOS event group that the HASH ISR sets, so it must be called from task context and needs USE_HAL_HASH_REGISTER_CALLBACKS set to 1 in the HAL configuration; the header enforces that with a compile-time error.

Both modes return the digest as a Lib::HAL::HASHPortBase::Sha256Digest (32 big-endian bytes) in a std::optional that is empty on failure or timeout. The IT mode takes a mutex, so concurrent callers from several tasks are serialized.

Important
The HASH peripheral is not present on the STM32F407xx device: its CMSIS header defines no HASH_BASE. The HASH peripheral belongs to other STM32F4 families (for example the STM32F415/F417 and STM32F437/F439). The module guard is HAL_HASH_MODULE_ENABLED; the STM32Cube template enables it, but the project's 'stm32f4xx_hal_conf.h' is not in the repository, so the guard is unverified here. Do not use this class on the STM32F407xx target.

Blocking digest

The port's open() must succeed before sha256() is called. The timeout bounds the HAL polling loop, so a stalled peripheral returns an empty optional instead of hanging.

#include <Lib/HAL/HASH.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <optional>
#include <span>
extern HASH_HandleTypeDef hhash; // Generated by CubeMX.
std::optional<Lib::HAL::HASHPort<Lib::HAL::DriverMode::BLOCKING>::Sha256Digest> hashOnce() noexcept {
constexpr std::array<uint8_t, 3> MESSAGE{0x61U, 0x62U, 0x63U};
Lib::HAL::HASHPort<Lib::HAL::DriverMode::BLOCKING> port(&hhash);
if (!port.open()) {
return std::nullopt;
}
const auto digest = port.sha256(std::span<const uint8_t>(MESSAGE), std::chrono::milliseconds(100));
static_cast<void>(port.close());
return digest;
}

Interrupt digest from a task

The IT port registers its HAL callbacks in its open() and unregisters them in its close(). A timed-out digest reinitializes the peripheral, so the next call starts from a clean state; a HAL error returns an empty optional without that step.

#include <Lib/HAL/HASH.hpp>
#include <RTOS.hpp>
#include <array>
#include <chrono>
#include <cstdint>
#include <optional>
#include <span>
extern HASH_HandleTypeDef hhash; // Generated by CubeMX.
void hashTask(void *) {
constexpr std::array<uint8_t, 3> MESSAGE{0x61U, 0x62U, 0x63U};
static Lib::HAL::HASHPort<Lib::HAL::DriverMode::IT> port(&hhash);
if (!port.open()) {
return;
}
while (true) {
const auto digest = port.sha256(std::span<const uint8_t>(MESSAGE), std::chrono::milliseconds(100));
if (digest.has_value()) {
// Use digest.value().
}
RTOS::delay(std::chrono::seconds(1));
}
}
