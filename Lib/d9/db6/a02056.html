Lib::HAL::UARTPort< DriverMode::BLOCKING >final

Description

Explicit specialized variant driving synchronous, blocking transfer paths.

Builds directly on "UARTPortBase" and stores the native handle itself, rather than through "Device<>", which brings an intrusive DeviceManager list link that only an interrupt-driven mode uses. A blocking transfer completes inside the HAL call itself, so it needs no RTOS event group, HAL callback registration, DeviceManager entry or abort; all of that is owned by "UARTPortAsync", shared by the "IT" and "DMA" specializations.

Also carries a "DriverDataDirection" tag ("RX" or "TX"), purely as a label for a caller that drives the two halves of a link through separate "UARTPort<BLOCKING>" instances, one per native handle.

◆ setBaudRate()

bool Lib::HAL::UARTPortBase< UARTPort< DriverMode::BLOCKING > >::setBaudRate ( uint32_t baudRate)
inlinenodiscardnoexceptinherited

Reconfigures the baud rate at runtime.

The HAL exposes no dedicated runtime setter, so the handle's init structure is updated and re-applied through "HAL_UART_Init()". Registered HAL callbacks survive the re-initialization. Available in every transfer mode.

Parameters
baudRateNew baud rate to apply, in bits per second.
Returns
"true" if the reconfiguration succeeded; "false" while a transfer is in flight.
