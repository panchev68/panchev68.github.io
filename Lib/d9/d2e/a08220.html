Lib::HAL::Timer::TimTimebase example

Runs a periodic task from a hardware timer with Lib::HAL::Timer::TimTimebase.

The update interrupt of the timer wakes the task blocked in Lib::HAL::Timer::TimTimebase::waitPeriod(), so the task runs once per period without polling. Call Lib::HAL::Timer::TimTimebase::start() from the task that will wait; the wrapper binds that task as the one to notify.

The ISR path is not defined by this header. HAL_TIM_PeriodElapsedCallback() is generated by CubeMX in 'main.c', and the forwarding call must be placed in its user-code section (see the first subsection). The waiting itself must run in a task, never in an ISR.

Usage

Hardware and CubeMX assumptions

  • The timer (here 'TIM1') is configured in CubeMX with its update interrupt enabled and its NVIC line enabled.
  • If this timer also drives the HAL tick, keep the HAL_IncTick() call from the forwarding code below.
  • Only one Lib::HAL::Timer::TimTimebase instance can exist per timer handle.

Forwarding the HAL period callback

CubeMX generates HAL_TIM_PeriodElapsedCallback() in 'main.c'. Add the forwarding call in its user-code section. Do not define the HAL callback in the library or in user code; that would clash with the CubeMX one.

// main.c
#include "main.h"
// USER CODE BEGIN PFP
void Lib_HAL_TimTimebase_PeriodElapsed(TIM_HandleTypeDef * htim);
// USER CODE END PFP
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef * htim) {
// USER CODE BEGIN Callback 0
// USER CODE END Callback 0
if (htim->Instance == TIM1) {
HAL_IncTick();
}
// USER CODE BEGIN Callback 1
Lib_HAL_TimTimebase_PeriodElapsed(htim);
// USER CODE END Callback 1
}

Periodic control task

The task calls Lib::HAL::Timer::TimTimebase::start() itself, then blocks on each period. A wait that times out returns false; the loop skips that cycle and keeps running.

#include <Lib/HAL/TIM/TimTimebase.hpp>
#include <RTOS.hpp>
class ControlLoop final {
public:
explicit ControlLoop(TIM_HandleTypeDef * timHandle) noexcept :
timebase(timHandle),
task(RTOS::Task::Config("Control", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::Timer::TimTimebase timebase; // Constructed before the task starts using it.
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!timebase.start()) {
return;
}
while (true) {
if (!timebase.waitPeriod(std::chrono::milliseconds(20))) {
continue; // Timeout: no period elapsed.
}
// Run one control cycle.
}
}
};

Changing the period

Lib::HAL::Timer::TimTimebase::setPeriod() writes the auto-reload register directly. Without preload enabled in CubeMX, a new value below the running counter makes the counter run to its maximum before it wraps.

void slowDown(Lib::HAL::Timer::TimTimebase & timebase) noexcept {
timebase.setPeriod(2U * 9999U); // Auto-reload value in timer ticks; period depends on the timer clock and prescaler.
}
