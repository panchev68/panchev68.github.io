Lib::MQTT::Client

Connects to an MQTT broker, subscribes, publishes and receives with Lib::MQTT::Client over a caller-supplied TCP transport.

Connects to an MQTT broker, subscribes, publishes and receives with Lib::MQTT::Client over a caller-supplied TCP transport.The client does not open a socket itself: pass a transport that satisfies Lib::MQTT::MqttTransport, for example a thin adapter over a Wiznet socket or a modem data-mode stream. All methods may be called from any task; incoming messages reach the handler from inside process(), so run it from one task. Nothing here may be called from an ISR.

Connecting and subscribing

The handler gets every fragment of an incoming message. A message larger than the receive buffer arrives in several calls: the topic and the total size are valid from the first one, and the payload is valid only during the call.

void onMessage(const Mqtt::Message & message) noexcept {
if (message.isFirst) {
// A new message starts: message.topic and message.totalSize are valid.
}
// Copy or parse message.payload now.
if (message.isLast) {
// The message is complete.
}
}
bool startSession(Mqtt & mqtt) noexcept {
if (mqtt.setMessageHandler(Mqtt::MessageHandler::fromFunction(&onMessage)) != Lib::MQTT::Status::SUCCESS) {
return false;
}
Mqtt::Config config{};
config.host = "broker.example.com";
config.port = 1883U;
config.clientId = "device-01";
config.keepAlive = std::chrono::seconds(30);
if (mqtt.connect(config) != Lib::MQTT::Status::SUCCESS) {
return false;
}
return mqtt.subscribe("devices/device-01/commands", Lib::MQTT::QoS::AT_LEAST_ONCE) == Lib::MQTT::Status::SUCCESS;
}

Publishing

With Lib::MQTT::QoS::AT_LEAST_ONCE the call returns after the broker acknowledged the message. It can run in another task than process(), because the client serializes the access.

void publishReading(Mqtt & mqtt, float celsius) noexcept {
char text[16];
const int length = std::snprintf(text, sizeof(text), "%.1f", static_cast<double>(celsius));
const std::span<const uint8_t> payload(reinterpret_cast<const uint8_t *>(text), static_cast<size_t>(length));
static_cast<void>(mqtt.publish("devices/device-01/temperature", payload, Lib::MQTT::QoS::AT_LEAST_ONCE));
}

Receiving task with keep-alive

process() waits in short slices, so the task can also send the periodic ping. Lib::MQTT::Status::TIMEOUT only means that nothing arrived; any other failure means the connection is gone and has to be rebuilt.

void receiveTask(Mqtt & mqtt) noexcept {
constexpr std::chrono::seconds KEEP_ALIVE_PERIOD{20};
RTOS::Timeout pingDue{KEEP_ALIVE_PERIOD};
while (true) {
const Lib::MQTT::Status status = mqtt.process(std::chrono::milliseconds(200));
if ((status != Lib::MQTT::Status::SUCCESS) && (status != Lib::MQTT::Status::TIMEOUT)) {
// The connection failed: reconnect with startSession() after a pause.
RTOS::delay(std::chrono::seconds(5));
static_cast<void>(startSession(mqtt));
continue;
}
if (pingDue.isExpired()) {
static_cast<void>(mqtt.ping());
pingDue.reset();
}
}
}
