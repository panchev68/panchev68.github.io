RTOS::Kernel

Description

Kernel abstraction for FreeRTOS management.

This class provides a comprehensive set of static methods for managing FreeRTOS kernel operations, including task scheduling, timing, critical sections, memory diagnostics, and system state queries. It ensures type safety, error handling, and resource tracking specifically tailored for embedded systems. The class includes RAII wrappers for automatic management of critical sections and scheduler suspension, as well as utilities for heap memory monitoring and CPU usage calculations.

Key features:

  • Scheduler control (start, end, suspend, resume)
  • Timing utilities (delays, tick conversions, uptime)
  • Critical section management (RAII-based)
  • Memory diagnostics and heap statistics
  • CPU usage monitoring
  • Context detection (task vs interrupt)
  • Interrupt management
Note
All methods are static and thread-safe where applicable. Requires FreeRTOS to be properly configured and initialized.
Attention
This class cannot be instantiated; all functionality is provided through static methods.

Delay current task by ticks.

Puts the current task into a blocked state for the specified number of ticks. During this time, other tasks can execute. The task will automatically unblock after the delay period. This is the fundamental delay function in FreeRTOS, used by other delay functions.

void RTOS::Kernel::enterCritical ( )
inlinestatic

Enter critical section.

Disables interrupts and task switching to create a critical section. Code within a critical section executes atomically and cannot be interrupted by other tasks or ISRs. Critical sections should be kept as short as possible to minimize system latency. Always pair with exitCritical() to restore normal operation.

◆ yield()

void RTOS::Kernel::yield ( )
inlinestatic

Yield processor to another task.

Forces the current task to yield control of the processor to another task of equal or higher priority that is ready to run. This is typically used in cooperative multitasking scenarios or when a task has completed its work and wants to allow other tasks to execute. Unlike vTaskDelay, this does not cause the task to enter a blocked state.
