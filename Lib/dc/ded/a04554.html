Lib::BSP::EEPROM::FlashEmulationF4final

Description

Stores 16-bit keyed records in two erasable flash sectors, appended as a log and compacted when a sector fills up.

Every record is an 8-byte header followed by its data, padded to a multiple of 4 bytes, because the flash is programmed in words. The data is written first, then the checksum, and the header word with the key and the length last, so a power loss leaves an erased header word and the record is simply absent. The newest record of a key wins. A sector holds a 16-byte header with a sequence number, written last during compaction, so the sector with the higher sequence is the active one. Reads go straight to the memory-mapped flash; writes and erases use the HAL.

Access is by key, not by address: compaction moves the live records, so an offset would not stay valid. Each key has its own length, from 1 to getMaxValueSize() bytes, stored in its record header; a new value of a different length simply replaces the old one. A value equal to the stored one is not written again.

Each write of a changed value consumes flash space. When the active sector is full, the latest value of every key is copied to the other sector, and the old sector is erased before the next compaction reuses it. The live values of all keys together must fit into one sector; dead records do not count, because compaction drops them. A record that a power loss left half written is skipped the same way: the append is refused until compaction clears the sector.

The two sectors must have the same size: two of the 16 KB sectors 0 to 3, or two of the 128 KB sectors 5 to 11. Programming uses 32-bit words, which needs the supply range of Config::voltageRange; the default is 2.7 V to 3.6 V.

Warning
Erasing and programming stall the CPU while code in the same flash bank is fetched, and this family has a single bank. Erasing a 128 KB sector takes up to about 2 s, a 16 KB one about 0.4 s; interrupts and tasks wait, so the watchdog must tolerate it. open() formats both sectors if the area holds no valid header, and every compaction erases one.
Call only from task context: the HAL polls the flash until each operation completes.
Important
The linker script must not place code or constants in the emulated sectors. Lower the end of the ROM region below the first sector, for example 'ICFEDIT_region_ROM_end = 0x0803FFFF' for sectors 6 and 7 of a 512 KB device.

size_t Lib::BSP::EEPROM::FlashEmulationF4::getFreeSpace ( )
inlinenodiscardnoexcept

Returns the bytes that can still be appended to the active sector without a compaction.

Dead records are not reclaimed here, so this value only falls until the next compaction. A damaged record at the end of the sector makes the sector unclean; then the space is reported as 0, because new records are refused until compaction.

Returns
Free bytes of the active sector, or 0 if the area is not open.

Returns the bytes occupied by records in the active sector, including dead ones.

The value counts every appended record, so it grows with each changed write until compaction copies the live values to the other sector and drops the rest. The live values alone are usually smaller.

Returns
Used bytes of the active sector, or 0 if the area is not open.
