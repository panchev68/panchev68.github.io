Detailed Description

Production date manager for OTP memory.

Manages production date storage in OTP memory with validation and write-once semantics. Each instance accesses a specific OTP address calculated from base address plus offset.

inlineexplicitnoexcept

Initialize with OTP memory offset.

Configures the ProduceDate instance to access OTP memory at the address calculated as: OTP::beginAddr() + offset. The offset must be within valid OTP memory bounds, otherwise an assertion will fail in debug builds.

Parameters
offsetOffset from OTP base address in bytes.
Precondition
offset must be less than (OTP::endAddr() - OTP::beginAddr())
Note
This constructor is marked noexcept as it only performs address calculation and validation via assert, with no dynamic allocation.

Check if OTP memory is empty.

Determines whether the OTP memory location contains uninitialized data. An empty OTP location contains the sentinel value 0xFFFFFFFF (factory-default erased state). This method is typically used as a precondition check before calling write().

Returns
true if OTP memory at flashAddress contains EMPTY_VALUE (0xFFFFFFFF), false if memory has been written with data (contains any other value).
Note
This is a const, noexcept operation that performs a simple read and comparison. No side effects or OTP locking/unlocking occurs.

◆ write()

Status Lib::System::ProduceDate::write ( const Date & value)
inlinenoexcept

Write production date to OTP memory.

Stores the production date at the configured OTP memory address with write-once semantics. Enforces that OTP memory must be empty before writing, as OTP is permanently written. Performs date validation, OTP unlock/write/lock sequence with automatic retry on failure.

Parameters
valueThe production date to write. Must pass isValid() validation.
Returns
Status::OK if date was successfully written and locked, Status::ERROR if memory is not empty, date is invalid, unlock/lock fails, or write fails.
Precondition
Memory at flashAddress must be empty (contains EMPTY_VALUE/0xFFFFFFFF). Check isEmpty() before attempting write. Writing to non-empty memory will fail.
Postcondition
On success, OTP memory at flashAddress is permanently locked with the date value. On failure, OTP remains locked and memory is unchanged.
Warning
This operation is permanent. Once written successfully, the date cannot be changed or erased. Use carefully and validate the date before calling this method.
Note
Failed writes trigger automatic retry once. Unlock/lock operations are asserted and will trap on failure in debug builds, indicating OTP interface issues.
