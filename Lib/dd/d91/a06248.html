RTOS::Mutex

Shows creating, locking and unlocking a priority-inheriting RTOS::Mutex.

Shows creating, locking and unlocking a priority-inheriting RTOS::Mutex.Covers a normal and a recursive mutex, a blocking lock with a timeout, a non-blocking try-lock, and the ownership query. The example runs in task context; a mutex must never be locked or unlocked from an ISR. For scope-based locking use the RTOS::MutexGuard wrapper.

Important
Unlock only from the task that holds the lock; unlocking from another task asserts in debug builds.

Normal mutex with timeout

RTOS::Mutex::lock() with a duration returns false when the timeout expires, and the protected resource must not be touched then.

#include <Lib/RTOS/FreeRTOS/Mutex.hpp>
#include <chrono>
using namespace std::chrono_literals;
void useBus() noexcept {
RTOS::Mutex bus(RTOS::Mutex::Type::NORMAL);
if (!bus.open()) {
return; // Creation failed: out of heap.
}
if (bus.lock(50ms)) {
// Shared resource used exclusively.
bus.unlock();
} else {
// Timed out after 50 ms; the resource was not touched.
}
bus.close();
}

Recursive mutex and try-lock

A recursive mutex can be locked again by the task that already holds it; each RTOS::Mutex::lock() needs a matching RTOS::Mutex::unlock().

#include <Lib/RTOS/FreeRTOS/Mutex.hpp>
void nestedUse() noexcept {
RTOS::Mutex nested(RTOS::Mutex::Type::RECURSIVE);
if (!nested.open() || !nested.lock()) {
return;
}
if (nested.tryLock()) {
// Same task acquired the recursive mutex again.
nested.unlock();
}
nested.unlock();
nested.close();
}

Ownership query

RTOS::Mutex::isOwnedByCurrentTask() is task-context only and is useful before a shared helper unlocks a mutex it did not lock.

#include <Lib/RTOS/FreeRTOS/Mutex.hpp>
void releaseIfHeld(RTOS::Mutex & bus) noexcept {
if (bus.isOwnedByCurrentTask()) {
bus.unlock();
}
