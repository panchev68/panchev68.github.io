@title Moving Average Computation with Fixed-Size Window

@title Moving Average Computation with Fixed-Size WindowThis example demonstrates the usage of the Integrator class for computing moving averages over a fixed-size window. The integrator is particularly useful in embedded systems for smoothing sensor data and noise reduction with minimal computational overhead.

Scenario

Processing temperature sensor readings to compute a running average over the last 10 samples. This is a common pattern in real-time sensor data filtering.

// Create an integrator for temperature values (int) with a 10-sample window
Lib::Helper::Integrator<int, 10> temperatureFilter;
// Simulate receiving sensor readings
int sensorReadings[] = {245, 248, 247, 249, 246, 244, 250, 248, 247, 249, 251, 248};
// Process each reading and obtain the running average
for (int reading : sensorReadings) {
int averageTemp = temperatureFilter.processValue(reading);
// averageTemp now contains the average of up to 10 most recent readings
// Output: 245, 246, 246, 247, 247, 246, 247, 247, 247, 247, 248, 248
}
// Alternatively, separate processing and computation steps
Lib::Helper::Integrator<float, 5> voltageFilter;
// Add values individually
voltageFilter.addValue(3.3f);
voltageFilter.addValue(3.31f);
voltageFilter.addValue(3.29f);
voltageFilter.addValue(3.32f);
voltageFilter.addValue(3.30f);
// Compute the result once the window is full (5 samples)
float smoothedVoltage = voltageFilter.computeResult(); // Returns 3.304
// Check if the window is full
if (voltageFilter.isWindowFull()) {
// Buffer contains exactly 5 samples
}
// Reset for a new batch of readings
voltageFilter.resetWindow();
// Use the operator() overload for functional processing
float result = voltageFilter(3.25f); // Equivalent to processValue(3.25f)

Notes

  • addValue() and processValue() operations complete in O(1) time.
  • computeResult() runs in O(1) time using the precomputed running sum.
  • No dynamic memory allocation; uses stack-based std::array for deterministic behavior.
  • Ideal for real-time embedded systems with strict timing constraints.
