Lib::HAL::Timer::TimOnePulse

Emits one pulse after a delay with Lib::HAL::Timer::TimOnePulse.

Emits one pulse after a delay with Lib::HAL::Timer::TimOnePulse. The delay and width are set with Lib::HAL::Timer::TimOnePulse::setTiming(); Lib::HAL::Timer::TimOnePulse::start() arms the timer, and the interrupt wakes the task blocked in Lib::HAL::Timer::TimOnePulse::waitPulseStart(). Call Lib::HAL::Timer::TimOnePulse::start() from that task, because it binds the task that will wait.

The header defines the HAL callback HAL_TIM_PWM_PulseFinishedCallback() itself, so do not define it elsewhere. The wake-up comes from the HAL pulse-finished callback for the channel, so the name Lib::HAL::Timer::TimOnePulse::waitPulseStart() does not mean the start of the pulse. The ISR path only notifies the task.

Usage

Hardware and CubeMX assumptions

  • Timer in One Pulse mode in CubeMX, with the output channel set to 'TIM_CHANNEL_1' or 'TIM_CHANNEL_2'. The wrapper asserts on any other channel.
  • Interrupt enabled in the NVIC.
  • One Lib::HAL::Timer::TimOnePulse per timer handle.

Generating a delayed pulse from a task

#include <Lib/HAL/TIM/TimOnePulse.hpp>
#include <RTOS.hpp>
class TriggerPulse final {
public:
explicit TriggerPulse(TIM_HandleTypeDef * timHandle) noexcept :
pulse(timHandle, TIM_CHANNEL_1),
task(RTOS::Task::Config("Pulse", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::Timer::TimOnePulse pulse; // Constructed before the task starts using it.
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!pulse.start()) {
assert(!"TriggerPulse: one-pulse mode failed to start");
return;
}
// Delay 100 ticks, then a 50-tick wide pulse; setTiming() keeps the width and delay in timer ticks.
pulse.setTiming(100U, 50U);
while (true) {
if (pulse.waitPulseStart(std::chrono::milliseconds(200))) {
// The pulse has finished; start the next cycle.
}
}
}
};

Validating timing

Lib::HAL::Timer::TimOnePulse::setTiming() asserts when the width is zero or when the delay plus width overflows 32 bits, and it then changes nothing. Check the values before calling it in release builds, where the assertion is disabled.

void retime(Lib::HAL::Timer::TimOnePulse & pulse, uint32_t delayTicks, uint32_t widthTicks) noexcept {
if (widthTicks == 0U) {
return;
}
pulse.setTiming(delayTicks, widthTicks);
}

Stopping

void disarm(Lib::HAL::Timer::TimOnePulse & pulse) noexcept {
if (!pulse.stop()) {
return;
}
