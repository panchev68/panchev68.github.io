Lib::HAL::FlashInterface example

Unlocks the flash controller, erases a sector and programs words with Lib::HAL::FlashInterface.

The class is a thin facade over the HAL flash functions and holds no state. Every method is Lib::HAL::FlashInterface::unlock() / Lib::HAL::FlashInterface::lock() bracketed: the controller is locked after reset, so unlock first, program or erase, then lock. Erase and program operations block the CPU until the hardware finishes, so they are not suitable for an ISR. Lib::HAL::FlashInterface::writeBuffer() also writes word by word and stops at the first failure, leaving the earlier words programmed.

The erase granularity and the programming width are chosen at compile time from the device macros: sectors where 'FLASH_TYPEERASE_SECTORS' is defined, pages where 'FLASH_TYPEERASE_PAGES' is defined, and word or doubleword programming where 'FLASH_TYPEPROGRAM_WORD' or 'FLASH_TYPEPROGRAM_DOUBLEWORD' is defined. On an unsupported device the method returns false.

Important
The module guard is 'HAL_FLASH_MODULE_ENABLED'; the project's 'stm32f4xx_hal_conf.h' is not in the repository, so that guard is unverified here, although the STM32Cube template enables it. On the STM32F407xx target the sector erase and word programming macros are available, so both methods are compiled in.
Warning
An erase destroys the whole sector, including any code or constants stored in it. Never erase the sector that holds the running firmware, and keep the code that performs the erase and the write in RAM, because the CPU cannot fetch from flash while the operation runs. Writes can only clear bits, so a word must be erased before it is programmed to a value that sets bits.

Usage

Erase a sector and program a block

Lib::HAL::FlashInterface::eraseSector() takes the sector index and the voltage range that matches the supply voltage; use the HAL constant 'FLASH_VOLTAGE_RANGE_3' for 2.7 V to 3.6 V on the STM32F407xx. Program the data only after the erase returns true, and check each step.

#include <Lib/HAL/Flash/FlashInterface.hpp>
#include <array>
bool storeSettings() noexcept {
constexpr uint32_t SETTINGS_SECTOR = 11U;
constexpr uint32_t SETTINGS_ADDRESS = 0x080E0000U;
static constexpr std::array<uint32_t, 4> SETTINGS{0x01U, 0x02U, 0x03U, 0x04U};
Lib::HAL::FlashInterface flash;
if (!flash.unlock()) {
return false;
}
bool isStored = flash.eraseSector(SETTINGS_SECTOR, FLASH_VOLTAGE_RANGE_3) &&
flash.writeBuffer(SETTINGS_ADDRESS, SETTINGS.data(), static_cast<uint32_t>(SETTINGS.size()));
isStored = flash.lock() && isStored;
return isStored;
}

Program one word

Lib::HAL::FlashInterface::writeWord() asserts that the address is 4-byte aligned. On a device that programs doublewords, the class reads the neighbouring word and programs the pair, so the neighbour must already be erased or hold the value it had before.

#include <Lib/HAL/Flash/FlashInterface.hpp>
bool writeOneWord(uint32_t address, uint32_t value) noexcept {
Lib::HAL::FlashInterface flash;
if (!flash.unlock()) {
return false;
}
const bool isWritten = flash.writeWord(address, value);
return flash.lock() && isWritten;
}
