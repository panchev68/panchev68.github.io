Lib::HAL::SPIPort example

Runs full-duplex and half-duplex transfers on an SPI bus with 'Lib::HAL::SPIPort<Lib::HAL::DriverMode::BLOCKING>', 'Lib::HAL::SPIPort<Lib::HAL::DriverMode::IT>' and 'Lib::HAL::SPIPort<Lib::HAL::DriverMode::DMA>'.

All three share one public surface, 'Lib::HAL::SPIPort::send()', 'Lib::HAL::SPIPort::receive()' and 'Lib::HAL::SPIPort::sendReceive()', so only the constructed mode changes.

The port takes a native 'SPI_HandleTypeDef' generated by CubeMX. It has no 'Config' struct: mode, clock and pins come from the CubeMX-generated 'MX_SPIx_Init()', and the port's 'Lib::HAL::SPIPort::open()' calls 'HAL_SPI_Init()' on that handle. Every transfer is bracketed by optional begin and end hooks, which typically drive a chip-select pin. Transfers take a buffer length from 1 to 65535 bytes and a timeout as any 'std::chrono::duration'.

Usage

Blocking transfers

The blocking mode runs each call to completion in the calling thread. It never yields to the RTOS, so use it from task context only; it is not safe from an ISR.

#include <Lib/HAL/GPIO.hpp>
#include <Lib/HAL/SPI.hpp>
#include <array>
extern SPI_HandleTypeDef hspi1;
bool readDeviceId(Lib::HAL::GPIO::Output & chipSelect) noexcept {
Lib::HAL::SPIPort<Lib::HAL::DriverMode::BLOCKING> port(&hspi1);
if (!port.open()) {
return false;
}
std::array<uint8_t, 4> command{0x9FU, 0x00U, 0x00U, 0x00U};
std::array<uint8_t, 4> reply{};
chipSelect.setLow();
const bool isExchanged = port.sendReceive(command, reply, std::chrono::milliseconds(10));
chipSelect.setHigh();
static_cast<void>(port.close());
return isExchanged;
}

Begin and end transaction hooks

'Lib::HAL::SPIPort::bindBeginTransactionFunc()' and 'Lib::HAL::SPIPort::bindEndTransactionFunc()' register a callback that runs before and after every 'Lib::HAL::SPIPort::send()', 'Lib::HAL::SPIPort::receive()' and 'Lib::HAL::SPIPort::sendReceive()' call. Use them to assert and release chip-select, so every call is framed without repeating the pin code. The callback is only referenced, so a capturing lambda must be an lvalue that outlives the binding.

#include <Lib/HAL/SPI.hpp>
#include <array>
extern SPI_HandleTypeDef hspi1;
namespace {
void selectFlash() noexcept {
HAL_GPIO_WritePin(FLASH_CS_GPIO_Port, FLASH_CS_Pin, GPIO_PIN_RESET);
}
void deselectFlash() noexcept {
HAL_GPIO_WritePin(FLASH_CS_GPIO_Port, FLASH_CS_Pin, GPIO_PIN_SET);
}
} // namespace
void writeEnable(Lib::HAL::SPIPort<Lib::HAL::DriverMode::BLOCKING> & port) noexcept {
port.bindBeginTransactionFunc(selectFlash);
port.bindEndTransactionFunc(deselectFlash);
constexpr std::array<uint8_t, 1> WRITE_ENABLE{0x06U};
static_cast<void>(port.send(WRITE_ENABLE, std::chrono::milliseconds(5)));
}

Interrupt-driven transfers

The 'IT' mode starts the transfer, then blocks the calling task on an RTOS event group until the HAL completion or error interrupt signals it or the timeout expires. It is therefore legal only from task context, and the task yields while the bus is busy. On a timeout or an error the port returns false; call Lib::HAL::SPIPortAsync::abort() from task context to stop a transfer that is still running.

Important
The port registers its own HAL callbacks, so the HAL configuration must set 'USE_HAL_SPI_REGISTER_CALLBACKS' to '1', or the translation unit fails to compile. The CubeMX-generated 'SPIx_IRQHandler()' must be enabled in the NVIC.
#include <Lib/HAL/SPI.hpp>
#include <RTOS.hpp>
#include <array>
extern SPI_HandleTypeDef hspi2;
class DisplayTask final {
public:
DisplayTask() noexcept :
port(&hspi2),
task(RTOS::Task::Config("Display", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::SPIPort<Lib::HAL::DriverMode::IT> port;
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!port.open()) {
return;
}
std::array<uint8_t, 8> frame{};
while (true) {
// Fill frame, then push it out; the task sleeps until the transfer completes.
if (!port.send(frame, std::chrono::milliseconds(20))) {
if (port.isBusy()) {
static_cast<void>(port.abort());
}
}
RTOS::delay(std::chrono::milliseconds(10));
}
}
};

DMA transfers

The 'DMA' mode has the same public calls and blocking policy as 'IT'; the data moves by DMA. The buffers must lie in memory the DMA controller can reach. On an F4 part that means not in CCM RAM, and Lib::HAL::isDmaReachable() is asserted on every buffer.

#include <Lib/HAL/SPI.hpp>
#include <array>
extern SPI_HandleTypeDef hspi3;
// Static storage in ordinary SRAM, not CCM RAM.
static std::array<uint8_t, 256> frameBuffer{};
bool pushFrame(Lib::HAL::SPIPort<Lib::HAL::DriverMode::DMA> & port) noexcept {
return port.send(frameBuffer, std::chrono::milliseconds(50));
}
