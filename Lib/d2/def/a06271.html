RTOS::MessageBuffer

Shows creating an RTOS::MessageBuffer, then sending and receiving one small message from a task.

Shows creating an RTOS::MessageBuffer, then sending and receiving one small message from a task. The example focuses on the API and leaves out task setup, so FreeRTOS must already be running.

  • A message buffer supports one writer and one reader; several writers or readers must serialize their calls themselves, e.g. with a RTOS::Mutex.
  • Every message costs its payload plus a length header, 4 bytes with the default configMESSAGE_BUFFER_LENGTH_TYPE, so a 256-byte buffer carries messages of up to RTOS::MessageBuffer::getMaxMessageSize() bytes (252).
  • From an interrupt use RTOS::MessageBuffer::sendFromISR() and RTOS::MessageBuffer::receiveFromISR() instead; the overloads that take a higherPriorityTaskWoken flag leave the portYIELD_FROM_ISR() call to the caller.

Send and receive a message

#include <Lib/RTOS/FreeRTOS/MessageBuffer.hpp>
#include <chrono>
#include <cstddef>
using namespace std::chrono_literals;
void taskSendReceiveExample() {
RTOS::MessageBuffer mb;
// Create a 256-byte underlying message buffer.
if (!mb.open(256)) {
return; // Creation failed: out of heap.
}
const char payload[] = "hello";
// Send from a task, blocking up to 100 ticks if necessary.
const size_t sent = mb.send(payload, sizeof(payload), static_cast<RTOS::MessageBuffer::TickType>(100));
static_cast<void>(sent);
// Receive the message, blocking up to 100 ms.
char recv[32] = {};
const size_t received = mb.receive(recv, sizeof(recv), 100ms);
// 'received' is the payload size, or 0 on timeout or if 'recv' was too small for the message.
if (received > 0 && received < sizeof(recv)) {
recv[received] = '\0';
}
mb.close();
}
