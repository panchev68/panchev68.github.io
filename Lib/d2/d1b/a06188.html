Lib::HAL::DeviceManager

Maps a native HAL handle, as seen inside an extern "C" HAL callback, back to the owning C++ object with Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>.

Maps a native HAL handle, as seen inside an extern "C" HAL callback, back to the owning C++ object with Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>. The objects are derived from Lib::HAL::Device<T_DEVICE, T_HANDLE>, which stores the handle and an intrusive list link.

This is the HAL-side ISR lookup. It is a different class from Lib::BSP::DeviceManager, which holds a periodic timer and a list of BSP drivers; the two share a name but nothing else. The HAL manager is a per-(device type, handle type) singleton, so the instance is selected by the template arguments. Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>::registerDevice() and Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>::unregisterDevice() take an RTOS critical section; the lookup, Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>::getDevice(), does not, so it is safe to call from an ISR. The list is walked linearly, so keep the number of instances per type small.

The device registers itself in its constructor and must not be destroyed while an ISR may still look it up. The example below uses a static instance, so that condition holds.

Warning
Lib::HAL::DeviceManager<T_DEVICE, T_HANDLE>::unregisterDevice() clears only the removed device's own link and does not relink its predecessor, so the devices that follow it in the list become unreachable. Until that is fixed, do not unregister a device that is not the last one registered, and do not rely on unregistration for correctness.

Usage

Derive a device from the base

Derive publicly from Lib::HAL::Device<T_DEVICE, T_HANDLE>, pass the native handle to its constructor, and register the object with the manager. Lib::HAL::Device<T_DEVICE, T_HANDLE>::getHandle() returns the handle that the lookup compares against.

#include <Lib/HAL/core/Device.hpp>
#include <Lib/HAL/core/DeviceManager.hpp>
#include <cstdint>
extern SPI_HandleTypeDef hspi1; // Generated by CubeMX.
class SpiBridge final : public Lib::HAL::Device<SpiBridge, SPI_HandleTypeDef> {
public:
explicit SpiBridge(SPI_HandleTypeDef * spiHandle) noexcept :
Device(spiHandle) {
static_cast<void>(Lib::HAL::DeviceManager<SpiBridge, SPI_HandleTypeDef>::instance().registerDevice(this));
}
void onTransmitComplete() noexcept {
transmitCount = transmitCount + 1U;
}
private:
volatile uint32_t transmitCount = 0U;
};
static SpiBridge spiBridge(&hspi1);

Look up the owner inside a HAL callback

The callback is defined once, by the application, and only forwards to the device. A null result means no instance owns that handle, so the callback must simply return.

#include <Lib/HAL/core/DeviceManager.hpp>
#include "SpiBridge.hpp" // Declares SpiBridge, as in the previous example.
extern "C" void HAL_SPI_TxCpltCallback(SPI_HandleTypeDef * hspi) {
SpiBridge * const bridge = Lib::HAL::DeviceManager<SpiBridge, SPI_HandleTypeDef>::instance().getDevice(hspi);
if (bridge != nullptr) {
bridge->onTransmitComplete();
}
}
