Lib::HAL::I2CPort

Runs master transfers on an I2C bus with 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::BLOCKING>', 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::IT>' and 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::DMA>'.

Runs master transfers on an I2C bus with 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::BLOCKING>', 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::IT>' and 'Lib::HAL::I2CPort<Lib::HAL::DriverMode::DMA>'. All three share one public surface ('Lib::HAL::I2CPort::masterTransmit()', 'Lib::HAL::I2CPort::masterReceive()', 'Lib::HAL::I2CPort::masterMemWrite()', 'Lib::HAL::I2CPort::masterMemRead()' and 'Lib::HAL::I2CPort::isReady()'), so only the constructed mode changes. The port is master-only.

The port takes a native 'I2C_HandleTypeDef' generated by CubeMX and has no 'Config' struct: the bus speed, addressing mode and pins come from the CubeMX-generated 'MX_I2Cx_Init()', which must run before 'open()'. Device addresses are 8-bit values with the R/W bit clear, for example '0xA0' for a 24C-series EEPROM at 7-bit address '0x50'.

Usage

Blocking master transfers

The blocking mode runs each transfer to completion in the calling thread and returns the status. Timeouts are rounded up to whole milliseconds and saturate at 'HAL_MAX_DELAY'. Blocking transfers never yield to the RTOS, so they may be used from task context only; they are not safe from an ISR.

#include <Lib/HAL/I2C.hpp>
#include <array>
extern I2C_HandleTypeDef hi2c1;
bool readEepromBlock() noexcept {
Lib::HAL::I2CPort<Lib::HAL::DriverMode::BLOCKING> port(&hi2c1);
if (!port.open()) {
return false;
}
constexpr uint16_t EEPROM_ADDRESS = 0xA0U;
std::array<uint8_t, 16> buffer{};
// Read 16 bytes starting at memory address 0x0000 with a 16-bit memory address.
const bool isRead = port.masterMemRead(EEPROM_ADDRESS, 0x0000U, I2C_MEMADD_SIZE_16BIT, buffer, std::chrono::milliseconds(100));
static_cast<void>(port.close());
return isRead;
}

Probing a device before use

'Lib::HAL::I2CPort::isReady()' sends up to 'trials' probes, each waiting at most the given timeout, and returns true on the first acknowledge. Call it before a transfer when a device may be absent or still powering up.

#include <Lib/HAL/I2C.hpp>
extern I2C_HandleTypeDef hi2c1;
bool waitForEeprom(Lib::HAL::I2CPort<Lib::HAL::DriverMode::BLOCKING> & port) noexcept {
return port.isReady(0xA0U, 3U, std::chrono::milliseconds(10));
}

Interrupt-driven transfers

The 'IT' mode starts the transfer, then blocks the calling task on an RTOS event group until the HAL completion or error interrupt signals it or the timeout expires. It is therefore only legal from task context, and the calling task yields while the bus is busy. On a timeout or error the port aborts the transfer and re-initializes the peripheral before returning false, so a failed call needs no manual recovery.

Important
The port registers its own HAL callbacks, so the HAL configuration must set 'USE_HAL_I2C_REGISTER_CALLBACKS' to '1', or the translation unit fails to compile. The CubeMX-generated 'I2Cx_EV_IRQHandler()' and 'I2Cx_ER_IRQHandler()' must be enabled in the NVIC.
#include <Lib/HAL/I2C.hpp>
#include <RTOS.hpp>
#include <array>
extern I2C_HandleTypeDef hi2c1;
class SensorTask final {
public:
SensorTask() noexcept :
port(&hi2c1),
task(RTOS::Task::Config("Sensor", 512, RTOS::Task::Priority::NORMAL), [this]() { run(); }) {
}
private:
Lib::HAL::I2CPort<Lib::HAL::DriverMode::IT> port;
RTOS::Task task; // Must stay the last member.
void run() noexcept {
if (!port.open()) {
return;
}
std::array<uint8_t, 2> reply{};
while (true) {
// Reads register 0x01 of the device at 7-bit address 0x48, with an 8-bit register address.
if (port.masterMemRead(0x90U, 0x01U, I2C_MEMADD_SIZE_8BIT, reply, std::chrono::milliseconds(20))) {
// Use reply.
}
RTOS::delay(std::chrono::milliseconds(100));
}
}
};

DMA transfers

The 'DMA' mode has the same public calls and blocking policy as 'IT'; the transfer data moves by DMA. The buffers must lie in memory the DMA controller can reach. On an F4 part that means not in CCM RAM, and Lib::HAL::isDmaReachable() is asserted on every buffer.

#include <Lib/HAL/I2C.hpp>
#include <array>
extern I2C_HandleTypeDef hi2c1;
// Static storage in ordinary SRAM, not CCM RAM.
static std::array<uint8_t, 32> dmaBuffer{};
bool writeEepromPage(Lib::HAL::I2CPort<Lib::HAL::DriverMode::DMA> & port) noexcept {
// Writes dmaBuffer to the EEPROM page at memory address 0x0000 with a 16-bit memory address.
return port.masterMemWrite(0xA0U, 0x0000U, I2C_MEMADD_SIZE_16BIT, dmaBuffer, std::chrono::milliseconds(50));
}

Aborting a stuck transfer

Lib::HAL::I2CPortAsync::abort() requests a master abort for the device address and waits for the abort event. It is available on the 'IT' and 'DMA' modes only, and it is called from task context. A blocking transfer cannot be aborted from another task.

#include <Lib/HAL/I2C.hpp>
extern I2C_HandleTypeDef hi2c1;
void cancelPendingTransfer(Lib::HAL::I2CPort<Lib::HAL::DriverMode::IT> & port) noexcept {
static_cast<void>(port.abort(0xA0U));
}
