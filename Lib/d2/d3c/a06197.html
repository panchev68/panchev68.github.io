Lib::HAL::OSPIPort

Runs a command with a data phase on the Octo-SPI controller through 'Lib::HAL::OSPIPort' in its three transfer modes: Lib::HAL::DriverMode::BLOCKING, Lib::HAL::DriverMode::IT and Lib::HAL::DriverMode::DMA.

Runs a command with a data phase on the Octo-SPI controller through 'Lib::HAL::OSPIPort' in its three transfer modes: Lib::HAL::DriverMode::BLOCKING, Lib::HAL::DriverMode::IT and Lib::HAL::DriverMode::DMA. The port wraps a CubeMX 'OSPI_HandleTypeDef' and does not configure the pins, clock or memory-mapped mode.

Each transfer is two steps: 'Lib::HAL::OSPIPort::command()' sends the instruction, address, alternate-byte and dummy phases described by a HAL 'OSPI_RegularCmdTypeDef', and the following 'Lib::HAL::OSPIPort::transmit()' or 'Lib::HAL::OSPIPort::receive()' moves the data phase. The size of the buffer must equal the 'NbData' of that command. The BLOCKING mode completes inside the HAL calls and works from any context. The IT and DMA modes wait on an RTOS::EventGroup, so their calls are task-only and assert when called from an ISR. The OCTOSPI interrupt handler must call HAL_OSPI_IRQHandler() for the handle.

Important
The OCTOSPI controller is not on the STM32F407 used by this library (F7, H7 and L4+ only), so the 'HAL_OSPI_MODULE_ENABLED' guard of this class has nothing to enable there. On that target the header compiles to nothing, so the example below applies only to a target with an OCTOSPI peripheral.
Warning
The IT and DMA modes register their own HAL callbacks in 'Lib::HAL::OSPIPort::open()', so the HAL configuration header must set 'USE_HAL_OSPI_REGISTER_CALLBACKS' to 1.

Setup and lifecycle

The CubeMX init code creates and configures the handle, including the flash size and the clock. 'Lib::HAL::OSPIPort::open()' runs HAL_OSPI_Init(); for the IT and DMA modes it also registers the callbacks and creates the event group. 'Lib::HAL::OSPIPort::close()' reverses this from task context. The port does not own the handle.

Blocking command and data phase

The timeouts are std::chrono durations. The example reads a block with the Quad I/O fast read opcode 0xEB of a serial flash; the instruction, address and dummy values are device-specific, and every field not set stays zero.

#include <Lib/HAL/OSPI.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern OSPI_HandleTypeDef hospi1;
bool readQuad(Lib::HAL::OSPIPort<Lib::HAL::DriverMode::BLOCKING> & port, uint32_t address, std::span<uint8_t> data) noexcept {
OSPI_RegularCmdTypeDef cmd{};
cmd.OperationType = HAL_OSPI_OPTYPE_COMMON_CFG;
cmd.FlashId = HAL_OSPI_FLASH_ID_1;
cmd.Instruction = 0xEBU;
cmd.InstructionMode = HAL_OSPI_INSTRUCTION_1_LINE;
cmd.InstructionSize = HAL_OSPI_INSTRUCTION_8_BITS;
cmd.Address = address;
cmd.AddressMode = HAL_OSPI_ADDRESS_4_LINES;
cmd.AddressSize = HAL_OSPI_ADDRESS_24_BITS;
cmd.DataMode = HAL_OSPI_DATA_4_LINES;
cmd.NbData = static_cast<uint32_t>(data.size());
cmd.DummyCycles = 6U;
if (!port.command(cmd, std::chrono::milliseconds(100))) {
return false;
}
return port.receive(data, std::chrono::milliseconds(100));
}

Interrupt-driven transfer

The IT mode uses the same two calls from a task. The OCTOSPI handler is the only interrupt hook: CubeMX 'OCTOSPI1_IRQHandler()' calls 'HAL_OSPI_IRQHandler(&hospi1)', which fires the callbacks that 'Lib::HAL::OSPIPort::open()' registered. A command without a data phase completes through the same event group.

#include <Lib/HAL/OSPI.hpp>
#include <array>
#include <chrono>
#include <cstdint>
extern OSPI_HandleTypeDef hospi1;
class FlashRegisterAccess final {
public:
FlashRegisterAccess() noexcept :
port(&hospi1) {
}
// Call from a task.
bool start() noexcept {
return port.open();
}
// Call from a task only; reads one status byte with a single-line data phase.
bool readStatus(uint8_t & status) noexcept {
OSPI_RegularCmdTypeDef cmd{};
cmd.OperationType = HAL_OSPI_OPTYPE_COMMON_CFG;
cmd.FlashId = HAL_OSPI_FLASH_ID_1;
cmd.Instruction = 0x05U;
cmd.InstructionMode = HAL_OSPI_INSTRUCTION_1_LINE;
cmd.InstructionSize = HAL_OSPI_INSTRUCTION_8_BITS;
cmd.AddressMode = HAL_OSPI_ADDRESS_NONE;
cmd.DataMode = HAL_OSPI_DATA_1_LINE;
cmd.NbData = 1U;
const std::span<uint8_t> data(&status, 1U);
return port.command(cmd, std::chrono::milliseconds(50)) && port.receive(data, std::chrono::milliseconds(50));
}
private:
Lib::HAL::OSPIPort<Lib::HAL::DriverMode::IT> port;
};

Error path and abort

A timed-out or failed phase returns false and the port stops its transfer, so the caller may issue the next command. If a task must release a blocked transfer from outside, 'Lib::HAL::OSPIPort::abort()' stops the controller and wakes the waiting task. The DMA mode requires the buffer to be reachable by the DMA controller; the port asserts on a CCM RAM buffer in a debug build.

#include <Lib/HAL/OSPI.hpp>
void cancelPending(Lib::HAL::OSPIPort<Lib::HAL::DriverMode::DMA> & port) noexcept {
static_cast<void>(port.abort());
}
