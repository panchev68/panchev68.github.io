Description

ST25R100 wake-up tuning singleton.

Polls the raw wake-up registers of "BSP::ST25R100::instance()" ("Driver::readWakeupDiagnostics()") and its lifetime min/max ADC range ("Driver::getWakeupADCRange()") every "POLL_PERIOD" into one Live Watch structure, so the wake-up threshold of "BSP::ST25R100" ("WAKEUP_DIFF_THRESHOLD", "ST25R100.cpp") can be picked from a measured margin between "no card" and "card at the wanted distance" instead of a guessed number.

Runs in its own task, not a "RTOS::TickClient" software timer: "readWakeupDiagnostics()" takes the reader's SPI mutex, which can block for a while if the discovery task is mid-transfer, and blocking the shared FreeRTOS timer daemon task stalls every other software timer in the project, not just this one.

Does not open the reader itself and starts no card discovery of its own: it only reads an already-open "BSP::ST25R100::instance()". Enable it alongside "RFIDCardTest" or "RFID" (whichever is active), not instead of them, and start it after that module in "Application::start()".

The values are the members of "APP::wakeupTuningWatch" ("WakeupTuningTest.cpp"); add that one expression to the IAR Live Watch and expand it — each field's own trailing comment documents it. Of note: the lifetime min/max fields update only when a wake-up interrupt actually fires, so they can sit at their reset extremes for as long as none happens, unlike the live ADC readings, which are polled directly every cycle regardless of interrupt activity. Set "resetRangeRequest" to 1 from the Live Watch to clear the min/max range and start a fresh soak run (e.g. right before moving a card toward the antenna); the test clears it back to 0 once done.

The state and the task live in an "Impl" defined in "WakeupTuningTest.cpp".
