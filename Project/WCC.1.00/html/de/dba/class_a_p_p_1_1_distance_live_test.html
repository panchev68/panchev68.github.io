Description

Live distance readout singleton.

Measures the distance every "PERIOD" in its own task, the same way "DistanceMeter" does.

12 V booster, start-up wait, first reading discarded, UART and booster released. Nothing is asserted: move a hand or a target in front of the transducer and read the values with the IAR Live Watch or a debugger.

The values are the members of one global structure, "APP::distanceLiveWatch" (DistanceLiveTest.cpp): add that one expression to the Live Watch and expand it; it fits on one screen. The less needed values (resets, memory, small counters, the register override slots) are in a second structure, "APP::distanceLiveWatchMore". Members: "distanceMeters", "distanceMillimeters", "distanceMicrometers", "minMeters", "maxMeters", "measurementCount", "failureCount" and "consecutiveFailureCount".

"isPowerAlwaysOn" is 0 by default (18.10.2026): the sensor powers up only for each measurement, as "DistanceMeter" does, with a "RAIL_SETTLE_TIME" wait right after the 12 V rail turns on before anything touches the sensor. Set it to 1 to keep the 12 V booster and the UART on all the time instead, so register writes last and the sensor does not restart each second (tried as a workaround for a suspected 12 V control issue, reverted once "RAIL_SETTLE_TIME" was added instead).

"isBreakEnabled" is 0 by default (18.10.2026: an unattended "__BKPT" with no debugger connected hard-faults the whole system, which also stops anything reading this test's published distance, e.g. "DistanceIndicatorTest"). Set it to 1 from the Live Watch to debug interactively: the test then stops once with "__BKPT(7)" after an echo dump or "__BKPT(4)" at the end of a frequency sweep, then clears it back to 0 (set it to 1 again for the next stop). "lastBreakStep" holds the number.

"pulseCount" is written to the burst pulse count (PULSE_P1 bits 4:0) and "gainRange" to the AFE gain range (DECPL_TEMP bits 7:6) after each power-up; "regPulseP1", "regCurrLimP1", "regInitGain", "regDecplTemp" and "regRecLength" are the registers as the device holds them.

The echo dumps are averaged in batches of "echoAverageCycles" into "echoAverage[128]": an echo that is there every time stays, noise averages out. "echoAverageNoise" is the noise floor, "echoAverageMax" the largest value after the ringing and "echoAverageMaxMicroseconds" its time after the burst (distance in mm is that time times 0.1715). BKPT #7 comes after each batch.

"isEchoDumpEnabled" (0 by default, 18.10.2026: extra load while diagnosing why detection drops after a few seconds) adds a burst whose received signal is read from the PGA460 echo memory into "echo[128]": the burst, the ringing, the noise and any echo over the record time (see "echoSlotMicroseconds").

"isComboRunning" (1 at start) measures "comboMeasurements" times in each of four modes (library or polled UART, deep sleep allowed or blocked), counts the failures in "failuresLibraryOpen", "failuresPolledOpen", "failuresLibraryLocked" and "failuresPolledLocked" and stops with "__BKPT(2)" at the end.

"objectCount" objects are read per burst and the first one over "minTimeOfFlight" is the distance (the ringing of the transducer is the first object at about 360 us); the first three are in "objectTimeOfFlight", "objectWidth" and "objectAmplitude".

"recLengthValue" is written to REC_LENGTH after each power-up, so the record time and the time scale of the echo array ("recordMicroseconds", "echoSlotMicroseconds") are known.

"isThresholdInitEnabled" writes a threshold map to the PGA460 after each power-up: the device does not keep it, and without it the detection runs with random thresholds. "devStat0Before" / "devStat0After" (bit 2 = THR_CRC_ERR) show the effect.

"uartBaudRate" is the baud rate USART1 is opened with at each power-up (115200 at start; 19200 was tried 18.10.2026 for more HSI16 timing margin but did not work on this board at all, reverted). The RX timeouts in "scaledPolls()" scale with it automatically, in case a different rate than 115200 is tried again.

"isDeepSleepBlocked" makes the test hold a deep sleep lock of the PowerManager (no STOP1 while it runs); it can be switched in the Live Watch at any time.

"isRequestChecksumSent" selects whether a request that expects an answer (UMR, system diagnostics, echo dump) carries a checksum byte (1, as the library driver sends it) or only the sync and command fields (0, as the PGA460 datasheet describes).

"isPolledExchange" selects the measurement path (1 polls the USART1 registers as "Diagnostics" does, 0 uses the library driver); "rawResponse", "rawByteCount" and "uartErrorFlags" show what the sensor actually sent back.

"stackFreeWords" (the least free stack of the task), "heapFreeBytes" and "heapMinimumFreeBytes" show a stack overflow or heap exhaustion. "startCount", "resetFlags" and "resetCause" tell whether the controller restarted by itself and why.

It also checks the transducer: after the distance an extra burst gives the transducer frequency and decay period ("transducerFrequencyHz", "decayPeriodMicroseconds"). The register override slots ("overrideMask", "overrideAddress", "overrideValue") let you write PGA460 registers from the Live Watch without a rebuild; slot 0 is on by default (18.10.2026) and sets FREQUENCY to the confirmed 40 kHz the board's transducer needs (the factory default is about 58 kHz and gives weak/distorted echoes) — clear bit 0 only to investigate the frequency itself again. "readbackAddress" / "readbackValue" read one register back every cycle. Both use the same UART, so it needs "ENABLE_DISTANCE_METER" off.
