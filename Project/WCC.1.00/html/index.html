WCC Firmware

Firmware for a solar-powered waste-container controller: STM32U575VGT6 (Cortex-M33), FreeRTOS, C++20. The controller admits users by RFID card, pulses a 5 l or 20 l lock, tracks the door sensor, charges the accumulator from the solar panel via an MPPT algorithm, measures fill level and temperature, and reports every event to an ESP32 module that holds the link to the central system.

The hardware (schematic, PCB) lives in a separate repository, WCC_Hardware; this repository is firmware only.

Hardware overview

Part Description
MCU STM32U575VGT6 (Cortex-M33), FreeRTOS
Power 12 V solar panel, OT12-GEL accumulator, LMR14030 charger driven through a DAC
Power monitoring Two INA219 (panel, accumulator) and one TMP102, all on I2C1
RFID ST25R100 on SPI3, NTAG21x cards
Distance PGA460 ultrasonic sensor on USART1
External temperature DS18B20 (1-Wire)
Communication ESP32 module on USART3
Storage External W25Q128 flash (16 MiB) on OCTOSPI1
Outputs OUT1..OUT4 lock drivers, a 12 V booster, front-panel buttons with LEDs, a buzzer

Layers

  • HAL — one function-local-static singleton per CubeMX peripheral handle (I2C1Port, Usart1Port, Usart3Port, SPI3Port, DAC1Port, OSPI1Port, RTCPort). BSP and APP go through these instead of touching the CubeMX handles directly. See Hardware Abstraction Layer.
  • BSP — board I/O singletons (Inputs, Outputs) and thin board-wiring facades over the chip drivers of the shared library X:/Lib/IAR/inc (INA219, TMP102, DS18B20, PGA460TPWRQ1, ST25R100, W25Q128JVSIQ). See Board Support Package.
  • APP — one module per task, each a singleton that owns its task, brings up its own hardware with retry, and publishes results through atomic getters: PowerSupply (MPPT, Supply12V, LowPower, nested ChargeIdle), DistanceMeter, ExternalThermometer, RFID, UserInterface, ComModule (ESP32 link) and StorageManager. Diagnostics runs a one-shot hardware check at start-up; Application starts every module. See Application Layer.

Core/, Drivers/, Middlewares/ and STM32U575VGT6.ioc are STM32CubeMX-generated; regenerating overwrites everything outside USER CODE blocks, so hand-written code stays in Project/ and RTOS/.

Building

  • Compiler: IAR EWARM 10.10.2, C++20 with libc++.
  • Project: EWARM/STM32U575VGT6.ewp, configuration STM32U575VGT6.

  • Full build from the command line:

    C:/iar/ewarm-10.10.2/common/bin/IarBuild.exe EWARM/STM32U575VGT6.ewp -build STM32U575VGT6
  • The firmware uses the header-only shared library X:/Lib/IAR/inc (outside this repository, read-only from here).
