Description

DeviceDriverBase Class.

This class provides the foundational interface for BSP device drivers, establishing a standard contract for initialization and periodic operations. It uses virtual methods to allow derived classes to implement hardware-specific logic while maintaining a consistent integration point with the system's driver management framework.

Key responsibilities include:

  • Providing default implementations for common driver operations
  • Defining pure virtual methods for mandatory driver functionality
  • Ensuring proper resource management through RAII principles

Subclasses should override init() for one-time setup and tick() for periodic updates. The base class handles default construction and destruction, allowing focus on hardware-specific implementation details.

Note
This is an abstract base class; direct instantiation is not intended.
Derived classes must implement the tick() method.

Derived BSP driver classes for implementation examples.

virtual void Lib::BSP::DeviceDriverBase::init ( )
inlinevirtual

Initializes the device driver.

Performs one-time initialization of the driver and associated hardware. This method should be called once during system startup to configure the device and prepare it for operation. Derived classes must implement hardware-specific initialization logic.

The base implementation provides a no-op default, allowing optional override. Initialization may include pin configuration, peripheral setup, and initial state establishment.

Note
Call this method before using other driver functionality.
Derived classes should call the base implementation if additional setup is needed.

virtual void Lib::BSP::DeviceDriverBase::tick ( )
pure virtual

Performs periodic driver processing.

Executes periodic maintenance and update operations for the driver. This method is called regularly by the system's driver management framework to handle time-based tasks such as status updates, watchdog resets, or background processing.

The base class declares this as a pure virtual method, requiring all derived classes to provide an implementation. Even if no periodic processing is needed, a minimal implementation should be provided.

Note
This method must be implemented by all derived classes.
Keep implementations lightweight to avoid blocking system operation.
