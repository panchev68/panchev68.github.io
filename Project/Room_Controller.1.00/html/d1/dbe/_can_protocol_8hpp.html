Description

CAN protocol of the new room panel with a TMP102 thermometer and any kind of display.

The controller is the Lib::Canbus server (node 0) and the panel is a client with node ID Config::panelNodeId. The link carries the room state, not pixels or segments: the panel owns its user interface and draws the state on whatever display it has, a TFT or seven segments alike. The link is event driven, nothing is sent while nothing changes. Every frame starts with a message type byte; multi-byte values are big-endian; temperatures are signed 0.1 degC.

Controller to panel:

  • STATE (8 bytes): type, regulator mode byte, fan speed, flags, setpoint, room temperature.
  • PARAMETERS (3 bytes): type, node address, setup byte.

Panel to controller:

  • announce (0 bytes): the panel started; the controller sends STATE and PARAMETERS again.
  • TEMPERATURE (4 bytes): type, panel thermometer reading, flags. Also the keep-alive.
  • SETPOINT (3 bytes): type, new setpoint chosen by the guest.
  • MODE (2 bytes): type, new regulator mode byte.
  • PARAMETER (4 bytes): type, parameter ID, value.

After every event the controller sends STATE and PARAMETERS again, so a value it changed or rejected reaches the panel, which serves as the acknowledgement. Only data is built and parsed here; the CAN peripheral is bound through Config::transmit and onFrameReceived(), so the class is testable without the RTOS.
