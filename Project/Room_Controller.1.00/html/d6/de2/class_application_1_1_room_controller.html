Description

Hardware-agnostic room controller: all I/O goes through the Config callbacks, so it runs on any STM32 part.

The RS485 task (RS485::Communication) answers the master and the panel task (Display::SerialPanel) polls the room panel. A software timer (RTOS::TickClient) runs the short control step every CONTROL_PERIOD: panel screens, door alarm, regulator and the countdowns. The slow work, saving the settings to the EEPROM and restarting, runs in the control task, which the step wakes when something is due. One mutex guards the state these share.

The room panel is the serial "Climate Control Display" with three digits, two keys and an SMT160 thermometer. The controller draws its screens and reads its keys and thermometer; the temperature is the average of the panel readings plus the calibration offset of the settings. The CAN panel is not used.

Each concern is a nested class: RS485Node answers the master, PanelLink runs the room panel, Session watches the RS485 session, RoomState changes mode, setpoint, address and setup, DeferredWork saves the settings and restarts, and ControlTick drives the control step. The state they share stays here.

A singleton: the node has one room. configure() builds it from the configuration once the settings are loaded, getInstance() reaches it from interrupt callbacks and other code.

The controller regulates on its own: a lost master changes nothing, it keeps the settings the master gave it. The one exception is the blocked mode: when the master is silent for Config::blockReleaseDelay, the block ends and the mode from before the block returns. The setpoint of SET_HIDDEN_TEMPERATURE is kept in the settings, so it survives a restart.

Behaviour kept from the legacy firmware: an open RS485 session (OPEN_NODE without CLOSE_NODE) restarts the node after Config::sessionTimeout, and the room temperature is saved as restore point before every restart and used until a panel temperature is available.
