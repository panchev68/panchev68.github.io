System::Parameters Class Reference

Description

System parameters manager for persistent storage.

This class manages the reading, writing, and validation of system parameters stored in EEPROM for the STM32-based system. It provides a unified interface to persist and retrieve configuration data, including display settings, peripheral groupings, and other critical system parameters. The class implements the Singleton pattern to ensure a single, globally accessible instance, promoting consistent parameter management across the application.

Key features include:

  • EEPROM-based non-volatile storage with checksum validation for data integrity.
  • Inline method implementations for optimized performance in embedded environments.
  • Thread-safe access through singleton design.
  • Comprehensive error handling and validation mechanisms.

Role of the type within the module or system: Serves as the central component for parameter persistence in the System namespace, enabling reliable configuration management and ensuring system settings are maintained across power cycles and software updates.

Important design decisions or considerations:

  • Singleton pattern prevents multiple instances and ensures consistent state.
  • CRC16 checksums provide robust data validation against corruption.
  • EEPROM storage allows for non-volatile parameter retention.
  • Inline methods reduce function call overhead in performance-critical paths.
Note
This class relies on BSP::M24C64W for low-level EEPROM operations and Lib::Helper::CRC16 for checksum computation. Ensure these dependencies are properly initialized.
Attention
Modifying parameters should be done cautiously to avoid system instability.

bool System::Parameters::isValid ( ) const
inline

Checks if parameters in EEPROM are valid by comparing checksums.

Performs integrity validation by reading the stored checksum from EEPROM and comparing it against a freshly calculated CRC16 checksum of the current parameter data. This method ensures that the stored parameters have not been corrupted due to power loss, hardware faults, or other environmental factors.

Returns
true if the stored checksum matches the calculated checksum (data is valid), false otherwise.
Precondition
EEPROM must be accessible for reading checksum.
Postcondition
No changes to internal state; purely a validation operation.
Note
This method recalculates checksum each time; consider caching for performance if needed.

◆ write()

bool System::Parameters::write ( )
inline

Writes parameters and checksum to EEPROM.

Writes the current parameter data to EEPROM storage along with a calculated CRC16 checksum for data integrity verification. The checksum is stored at the end of the EEPROM to enable validation during subsequent reads. This ensures that corrupted or incomplete data can be detected.

Returns
true if both data and checksum were written successfully, false otherwise.
Precondition
EEPROM must be present and accessible; internal data must be valid.
Postcondition
If successful, EEPROM contains updated parameter data and checksum; otherwise, EEPROM state unchanged.
Note
Checksum calculation uses Lib::Helper::CRC16 for reliable error detection.
Attention
Writing operations may take time; avoid calling in time-critical sections.
